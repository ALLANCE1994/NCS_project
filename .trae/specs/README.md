## 一、目录结构

```
.trae/specs/
├── template-spec/              # Spec 工作流模板目录
│   ├── spec.md                 # 需求大纲模板
│   ├── tasks.md                # 任务拆解模板
│   ├── checklist.md            # 验收清单模板
│   └── README.md               # Spec 模板使用说明
├── template-plan/              # Plan 工作流模板目录
│   ├── plan.md                 # 执行计划模板
│   └── README.md               # Plan 模板使用说明
├── YYYYMMDD_任务名称_Spec/      # 实际 Spec 任务目录
│   ├── spec.md
│   ├── tasks.md
│   └── checklist.md
├── YYYYMMDD_任务名称_Plan/      # 实际 Plan 任务目录
│   └── plan.md
└── README.md                   # 本文件
```

## 二、命名规则

### 2.1 文件夹命名

#### 模板文件夹

| 类型 | 命名格式 | 说明 |
|------|----------|------|
| Spec 模板 | `template-spec` | 存放 spec.md/tasks.md/checklist.md 模板 |
| Plan 模板 | `template-plan` | 存放 plan.md 模板 |

#### 实际任务文件夹

| 类型 | 命名格式 | 示例 |
|------|----------|------|
| Spec 任务 | `YYYYMMDD_任务名称_Spec` | `20260520_多智能体规则解耦_Spec` |
| Plan 任务 | `YYYYMMDD_任务名称_Plan` | `20260520_技能模板优化_Plan` |

#### 命名约束

- 小写字母 + 数字 + 下划线
- 无中文、无特殊字符（除下划线）
- 任务名称简洁不冗余（≤20字）

### 2.2 文件命名

| 工作流 | 固定文件名 | 说明 |
|--------|------------|------|
| Spec | `spec.md` | 需求大纲 |
| Spec | `tasks.md` | 任务拆解 |
| Spec | `checklist.md` | 验收清单 |
| Plan | `plan.md` | 执行计划 |
| 配套 | `README.md` | 使用说明 |

#### 命名约束

- 全小写
- 无后缀修改
- 不添加额外前缀/后缀
- 确保 MTC 自动识别

## 三、存放路径规范

### 3.1 根目录

- 工作流所有文件统一存放于：`.trae/specs/`
- 此为 MTC 原生识别目录，不可修改路径

### 3.2 路径约束

- 所有路径使用**相对路径**（相对于项目根目录）
- 路径书写：全小写、用 `/` 分隔目录
- 不包含空格、中文、特殊字符
- 禁止在 `.trae/specs/` 下自建无关子目录（如 `temp/`、`backup/`）

## 四、调用使用细则

### 4.1 工作流调用方式

#### Spec 工作流（复杂系统级任务）

1. 在 MTC 对话输入框输入 `/`，从弹出列表中选择「Spec」
2. 或直接输入指令：`/spec 任务描述`
3. 生成文档后，MTC 会暂停执行
4. 手动确认文档内容（可编辑修改）
5. 确认后继续执行

#### Plan 工作流（中小型模块任务）

1. 在 MTC 对话输入框输入 `/`，从弹出列表中选择「Plan」
2. 或直接输入指令：`/plan 任务描述`
3. 生成 plan.md 后，确认计划无误
4. MTC 会按计划逐步执行

### 4.2 文档使用细则

#### 模板使用

- 新建任务时，复制对应模板目录下的文件到新任务目录
- 不直接修改模板文件

#### 文档编辑

- 遵循官方文档格式（段落层级、句式、验收清单写法）
- 不擅自修改结构

#### 状态更新

- 任务执行过程中，实时更新 tasks.md（任务进度）
- 实时更新 checklist.md（验收状态）
- 确保与实际执行一致

#### 版本管理

- 所有工作流文档纳入 Git 版本控制
- 提交时备注任务进度
- 示例：「Spec 文档 - 多智能体规则解耦 - 初稿确认」

### 4.3 异常处理

| 问题 | 检查项 |
|------|--------|
| 调用工作流后未生成文档 | 路径是否为 `.trae/specs/`、命名是否符合规则、MTC 是否重启生效 |
| 文档无法被 MTC 识别 | 文件名是否为官方固定名称、路径是否正确、无特殊字符 |
| 需修改已生成的工作流文档 | 直接编辑对应文件，编辑后告知 MTC 同步更新执行进度 |

## 五、工作流选择指南

| 工作流 | 适用场景 | 文件数量 | 复杂度 |
|--------|----------|----------|--------|
| Spec | 复杂系统级任务、多模块协作、需要完整需求分析 | 3个 | 高 |
| Plan | 中小型模块任务、单智能体可完成、步骤清晰 | 1个 | 低 |

### Spec 适用条件

- 涉及多个智能体协作
- 需要完整的需求分析和技术方案
- 任务周期较长（>3天）
- 需要风险评估和里程碑管理

### Plan 适用条件

- 单一智能体可完成
- 任务步骤清晰明确
- 任务周期较短（≤3天）
- 无复杂依赖关系

## 六、状态符号说明

| 符号 | 含义 | 使用场景 |
|------|------|----------|
| ⏳ | 待启动/待执行 | 任务尚未开始 |
| 🔄 | 进行中/执行中 | 任务正在执行 |
| ✅ | 已完成 | 任务已完成 |
| ❌ | 阻塞 | 任务被阻塞 |
| ⬜ | 未验收/未就绪 | 验收项未检查 |
