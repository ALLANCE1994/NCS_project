## P0 最高优先级（9个）
- P0_01 规则分层管理：前置校验、安全互锁、核心规则常驻
- P0_02 决策权限边界：L1人决策、L2人确认、L3 AI执行
- P0_03 VibeCoding三阶段：战略定型→工程定型→工程落地不可跳步
- P0_04 Not-To-Do List：禁止功能清单全员检查
- P0_05 防幻觉全局规则：RAG溯源铁律无资料停止作答
- P0_06 阶段闸门强制：阶段出口条件@V审核禁止跳步
- P0_07 架构文档强制评审：文档先行三方评审
- P0_08 小步快跑强制：单步≤50行每步验证
- P0_09 项目经理唤醒：@M无条件唤醒全部智能体

## P1 核心优先级（4个）
- P1_01 防幻觉速查卡：4条核心规则速查→详见P0_05
- P1_02 三层回滚防线：L1 Feature Flags、L2 git revert、L3 Worktree
- P1_03 前期规划深度：各阶段完成标准禁止跳步
- P1_04 上下文质量：结构化输入、交付型输出

## P2 标准优先级（6个）
- P2_01 文档提炼流程：双层提炼预处理→精炼→审核→入库
- P2_02 小步快跑：四控制法禁止顺手优化
- P2_03 文档同步管理：规则变更必须同步更新文档
- P2_04 文档保存规范：代码保存路径Git提交工作记录
- P2_05 任务后合规检查：@V分层检查P0/P1/灵魂/职责/标准
- P2_06 项目计划制定：波特图格式无时间节点依赖驱动

## P3 辅助优先级（4个）
- P3_01 无伤节流：剔除冗余保留干货一事一议
- P3_02 外部知识查询：知识库无内容时引导查询正点原子
- P3_03 智能体标注：任务执行前标注智能体名字
- P3_04 极简输出风格：默认极简节省token客户要求时再展开

## 冲突解决
- P0 vs P1/P2/P3→P0优先不可违背
- P1 vs P2/P3→P1优先
- P2 vs P3→P2优先
- 同优先级冲突→文件编号小优先或@V裁决
