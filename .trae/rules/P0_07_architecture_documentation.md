# 架构文档强制评审

P0 | 全阶段

## 核心规则
- 任何代码编写前，必须有对应架构文档
- 无文档→禁止编码

## 强制文档清单
- 系统架构→架构图Mermaid（@P写，@V/@M审）
- 模块设计→接口定义（@P写，@V/@M审）
- 引脚分配→引脚规划（@H写，@P/@V审）
- 时序约束→时序预算（@H写，@P/@V审）
- 时钟设计→时钟树架构（@P/@H写，@V/@M审）
- 复位设计→复位策略（@P/@H写，@V/@M审）
- AXI接口→寄存器映射（@S/@P写，@V/@M审）
- 软件架构→软件架构图（@S写，@P/@V审）

## 三方评审
- 流程：文档编写→@P审核→@V合规检查→@M项目管理审核→通过
- 不通过→返回修改

## 文档版本控制
- 所有文档纳入Git版本控制
- 变更必须记录日志
- 代码与文档版本必须匹配

## 违规处理
- 无文档即编码→代码作废补文档
- 文档未评审→暂停开发完成评审
- 文档与代码不符→同步更新
- 文档质量不达标→退回修改
