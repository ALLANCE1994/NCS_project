## 一、决策背景

M2阶段原计划"顶层在M3.5之后编写，AXI在M4实现"，但未完成详细的PS-PL接口架构设计，导致M4实现阶段反复遇到技术问题。本文档补充M2缺失的关键架构决策。

---

## 二、方案对比分析

### 2.1 候选方案

| 方案 | 技术实现 | 优点 | 缺点 | 适用场景 |
|------|----------|------|------|----------|
| **A: AXI4-Lite直接控制** | PS通过AXI-Lite读写PL寄存器 | 标准接口、PYNQ原生支持、时序简单 | 需要RTL实现AXI从接口 | 控制类应用 |
| **B: AXI GPIO** | 使用Xilinx AXI GPIO IP核 | 无需自定义RTL、快速集成 | GPIO位宽限制、不灵活 | 简单IO控制 |
| **C: AXI Stream + DMA** | 数据流通过DMA搬运 | 高带宽、适合大数据量 | 复杂、需要驱动开发 | 视频/高速采集 |
| **D: EMIO + 自定义协议** | PS通过EMIO扩展自定义协议 | 灵活 | 非标准、PYNQ不支持 | 特殊需求 |

### 2.2 NV色心项目需求分析

| 需求 | 分析 | 方案匹配 |
|------|------|----------|
| 控制DDS频率/相位 | 寄存器读写，低频 | A或B |
| 配置扫描参数 | 寄存器读写，低频 | A或B |
| 读取ADC数据 | 寄存器读取，中频(10MHz) | A |
| 读取LIA/IIR结果 | 寄存器读取，低频 | A |
| 启动/停止扫描 | 控制信号，低频 | A或B |
| PYNQ原生支持 | 必须 | A或C |

### 2.3 决策结论

> **选择方案A: AXI4-Lite直接控制**

**决策理由**:
1. NV色心控制以寄存器配置为主，数据量小，AXI4-Lite完全满足
2. AXI GPIO位宽限制（32位），无法灵活映射多个寄存器
3. AXI Stream + DMA过于复杂，当前MVP不需要高带宽
4. AXI4-Lite PYNQ原生支持，Overlay自动生成驱动
5. 虽然需要RTL实现，但属于标准设计，风险可控

## 三、时钟架构决策

### 3.1 方案对比

| 方案 | 时钟源 | 优点 | 缺点 |
|------|--------|------|------|
| **M3方案** | 外部50MHz晶振 | 独立、稳定 | 需要外部时钟芯片 |
| **M4方案** | PS7 FCLK_CLK0 | 集成、无需外部时钟 | 依赖PS启动 |

### 3.2 决策结论

> **选择PS7 FCLK_CLK0 (50MHz)**

**决策理由**:
1. 简化硬件设计，无需外部时钟芯片
2. PS启动后自动提供时钟，上电时序简单
3. 50MHz满足所有子模块时序要求（DDS/ADC/SCAN/CORDIC/IIR）
4. 与AXI接口时钟同源，简化跨时钟域设计

**时钟分配**:
```
PS7 FCLK_CLK0 (50MHz)
    ├── M_AXI_GP0_ACLK (PS Master端口时钟)
    ├── AXI Interconnect时钟
    └── top_odmr s_axi_aclk (PL系统时钟)
```

## 四、复位架构决策

### 4.1 方案对比

| 方案 | 复位源 | 优点 | 缺点 |
|------|--------|------|------|
| 外部复位按键 | 用户按键 | 独立控制 | 需要外部电路 |
| **PS7 FCLK_RESET0_N** | PS生成 | 集成、自动释放 | 依赖PS启动 |

### 4.2 决策结论

> **选择PS7 FCLK_RESET0_N**

**决策理由**:
1. 与FCLK_CLK0同源，时序匹配
2. PS启动后自动释放复位，无需用户干预
3. 简化硬件设计

## 五、顶层模块版本决策

### 5.1 两个版本定义

| 版本 | 名称 | 用途 | 时钟/复位源 |
|------|------|------|-------------|
| **V1** | top_odmr_pl | M3纯PL验证 | 外部50MHz/外部复位 |
| **V2** | top_odmr_ps | M4 PS集成 | PS7 FCLK_CLK0/FCLK_RESET0_N |

### 5.2 决策结论

> **维护两个版本，通过Feature Flag切换**

**决策理由**:
1. M3版本已完成验证，保留作为回滚基准
2. M4版本基于M3修改，保持子模块不变
3. Feature Flag实现版本切换，便于调试

**实现方式**:
```vhdl
-- 在top_odmr中通过generic选择版本
generic (
    FEATURE_PS_MODE : std_logic := '1'  -- '1'=PS模式, '0'=PL模式
);
```

## 六、AXI Interconnect配置决策

### 6.1 配置参数

| 参数 | 值 | 说明 |
|------|-----|------|
| NUM_MI | 1 | 1个Master（连接top_odmr） |
| NUM_SI | 1 | 1个Slave（连接PS7） |
| 数据宽度 | 32 | AXI4-Lite标准 |
| 地址宽度 | 32 | 4GB地址空间 |

### 6.2 地址映射

| 设备 | 地址范围 | 大小 |
|------|----------|------|
| top_odmr AXI-Lite | 0x4000_0000 ~ 0x4000_0FFF | 4KB |

## 七、关键设计约束

### 7.1 AXI4-Lite协议约束

1. **地址对齐**: 32位地址对齐（地址[1:0]=00）
2. **字节选通**: s_axi_wstrb[3:0]控制写字节
3. **响应码**: 00=OKAY，10=SLVERR
4. **时序**: 写操作先AW后W，读操作AR后R

### 7.2 时序约束

| 参数 | 值 | 说明 |
|------|-----|------|
| 时钟频率 | 50MHz | FCLK_CLK0 |
| 时钟周期 | 20ns | - |
| WNS目标 | >1ns | 时序余量 |
| TNS目标 | =0 | 无违规 |
