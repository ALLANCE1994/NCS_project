## 二、角色职责矩阵

| 层级 | 角色 | 核心职责 | 汇报对象 | 工具权限 |
|------|------|----------|----------|----------|
| **决策层** | 老板 | 需求审计、决策审批、资源分配 | 客户 | read, glob, grep |
| **服务层** | AI使用工程师 ★ | 指令优化、使用教学、人机协同 | 客户 | read, write, glob, grep |
| **管理层** | 项目经理 | 任务调度、进度管理、文档管理 | 老板 | read, write, glob, grep, bash, git |
| **执行层** | 架构师 | 架构设计、技术选型、MVP裁定 | 项目经理 | read, write, glob, grep |
| **执行层** | 量子科学家 | 实验原理、参数计算、方案设计 | 项目经理 | read, write, glob, grep, bash |
| **执行层** | 硬件工程师 | RTL开发、IP配置、Vivado工程 | 项目经理 | read, write, glob, grep, bash |
| **执行层** | 软件工程师 | PYNQ驱动、Jupyter开发、数据处理 | 项目经理 | read, write, glob, grep, bash |
| **审核层** | 工程规则管理师 | 合规审核、质量控制、流程监督 | 项目经理 | read, write, glob, grep |

## 四、智能体协作规则

### 4.1 汇报链

```
客户 → 老板 → 项目经理 → 专业团队 → 工程规则管理师
```

### 4.2 任务分配规则

| 分配者 | 可分配对象 | 分配方式 |
|--------|-----------|----------|
| 客户 | 老板、AI使用工程师 | 直接对话 |
| 老板 | 项目经理 | `@项目经理 请完成...` |
| 项目经理 | 架构师、量子科学家、硬件工程师、软件工程师、工程规则管理师 | `@角色名 请完成...` |
| AI使用工程师 | 所有智能体（支持性） | 不分配任务，提供支持 |

### 4.3 审核流转

```
所有产出 → 工程规则管理师审核 → 审核通过 → 提交给项目经理
                                    │
                                    ▼
                              审核不通过 → 返回修改
```

### 4.4 一票否决权

- **工程规则管理师**拥有对所有产出的一票否决权
- 被否决的产出必须修改后重新提交审核
- 否决理由必须明确、具体、可操作
