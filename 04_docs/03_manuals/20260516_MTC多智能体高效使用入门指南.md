## 一、快速入门

### 1.1 什么是Trae Solo MTC？

Trae Solo MTC是一个多智能体协作平台，允许你同时调度多个AI角色完成复杂任务。每个智能体都有明确的职责、权限和工作规范。

### 1.2 核心概念

| 概念 | 说明 |
|------|------|
| **智能体（Agent）** | 具有特定职责和权限的AI角色 |
| **调度** | 通过@角色名的方式分配任务 |
| **并行** | 同时让多个智能体工作 |
| **上下文** | 当前对话中的所有信息 |

### 1.3 你的智能体团队

| 角色 | 职责 | 什么时候找TA |
|------|------|--------------|
| **老板** | 最高决策，需求审计 | 有新需求、需要决策 |
| **AI使用工程师** | MTC使用指导，指令优化 | 不知道怎么用MTC |
| **项目经理** | 任务调度，进度管理 | 需要分配任务、了解进度 |
| **工程规则管理师** | 质量审核，风险控制 | 需要审核产出 |
| **架构师** | 架构设计，技术选型 | 需要设计方案 |
| **量子科学家** | 实验原理，参数计算 | 需要科学指导 |
| **硬件工程师** | PL端开发，Vivado工程 | 需要硬件开发 |
| **软件工程师** | PS端开发，PYNQ驱动 | 需要软件开发 |

## 二、基础操作

### 2.1 单智能体调度

**语法**：
```
@角色名 请完成以下任务：
[任务描述]
```

**示例**：
```
@硬件工程师 请编写一个LED闪烁的VHDL模块：
- 输入：100MHz时钟、复位信号
- 输出：LED控制信号
- 闪烁频率：1Hz
```

### 2.2 多智能体并行调度

**语法**：
```
@角色A 请完成XXX任务
@角色B 请同时完成YYY任务

两个任务独立，请并行执行。
```

**示例**：
```
@硬件工程师 请设计PL端的脉冲发生模块
@软件工程师 请设计PS端的PYNQ驱动接口

两个任务独立，请并行执行。
```

### 2.3 任务模板使用

**开发任务模板**：
```markdown
@目标智能体 请完成以下开发任务：

【任务目标】一句话描述要做什么
【改动边界】仅处理XXX，不涉及YYY
【输入条件】当前状态/已有资源
【输出要求】交付物清单
【验收标准】如何验证完成
【禁止事项】不进行XXX操作

请先确认理解，再开始执行。
```

## 三、常用指令模板

### 3.1 需求提交模板

```markdown
@老板 请审计以下需求：

【需求描述】
一句话描述你想做什么

【期望目标】
希望达成什么效果

【约束条件】
- 时间约束：...
- 资源约束：...
- 技术约束：...

请进行DNA提取和需求脱水。
```

### 3.2 设计任务模板

```markdown
@架构师 请设计以下模块：

【设计目标】要实现什么功能
【约束条件】资源限制/性能要求
【已有方案】当前设计（如有）
【参考资源】相关文档/案例

请输出设计方案和接口定义。
```

### 3.3 开发任务模板

```markdown
@硬件工程师/@软件工程师 请完成以下开发任务：

【任务目标】一句话描述要做什么
【改动边界】仅处理XXX，不涉及YYY
【输入条件】当前状态/已有资源
【输出要求】交付物清单
【验收标准】如何验证完成
【禁止事项】不进行XXX操作

请先确认理解，再开始执行。
```

### 3.4 调试任务模板

```markdown
@硬件工程师/@软件工程师 请协助调试以下问题：

【问题描述】一句话概括错误现象
【环境信息】框架版本/依赖版本
【重现步骤】1)... 2)... 3)...
【错误信息】完整错误信息
【预期结果】期望的正常行为
【已尝试方案】已经做过什么

请分析根因并给出修复方案。
```

### 3.5 审核请求模板

```markdown
@工程规则管理师 请审核以下产出：

【审核对象】文件/模块/方案名称
【审核类型】代码审核/文档审核/方案审核
【相关背景】产出背景和目的

请按照三维过滤网标准进行审核。
```

### 3.6 进度查询模板

```markdown
@项目经理 请汇报当前项目进度：

【查询范围】整体进度/特定任务
【关注点】进度/风险/阻塞

请输出当前状态和下一步计划。
```

## 四、高效使用技巧

### 4.1 上下文管理

#### 问题
对话越长，AI越容易"忘记"之前的内容。

#### 解决方案
1. **定期压缩**：使用 `/compact` 命令压缩上下文
2. **分阶段对话**：不同阶段的任务分开对话
3. **关键信息保存**：重要信息及时保存到知识库

#### 示例
```
请将以下设计决策保存到知识库：
[设计决策内容]
```

### 4.2 任务拆解原则

#### 原则
- 每个任务控制在1-3天内完成
- 任务边界清晰，不重叠
- 验收标准明确

#### 示例
```
❌ 错误：@硬件工程师 请完成整个脉冲发生器的设计

✅ 正确：@硬件工程师 请完成脉冲发生器的以下子模块：
1. 时钟分频模块（预计0.5天）
2. 脉冲计数模块（预计0.5天）
3. 输出控制模块（预计1天）
```

### 4.3 并行调度技巧

#### 何时并行
- 任务之间没有依赖关系
- 任务由不同智能体负责
- 任务输出不相互影响

#### 示例
```
✅ 可以并行：
@硬件工程师 请设计PL端模块A
@软件工程师 请设计PS端接口B
（硬件和软件开发可以并行）

❌ 不能并行：
@架构师 请设计模块A的架构
@硬件工程师 请实现模块A
（硬件工程师需要等架构师的输出）
```

### 4.4 审核前置

#### 原则
所有产出在提交前都要经过审核。

#### 流程
```
开发完成 → @工程规则管理师 审核 → 审核通过 → 提交
                                    │
                                    ▼
                              审核不通过 → 修改 → 重新审核
```

## 五、常见问题与解决方案

### 5.1 AI输出不符合预期

#### 原因
- 指令不够具体
- 缺少上下文
- 没有明确输出格式

#### 解决方案
```markdown
@AI使用工程师 请帮我优化以下指令：

[原始指令]

期望输出：[描述你期望的输出]
```

### 5.2 任务执行卡住

#### 原因
- 任务太大，需要拆解
- 缺少必要信息
- 智能体之间等待

#### 解决方案
```markdown
@项目经理 请分析以下任务的阻塞原因：

[任务描述]

当前状态：[描述当前状态]
```

### 5.3 多智能体协作混乱

#### 原因
- 任务分配不清晰
- 汇报关系不明确
- 输出格式不统一

#### 解决方案
```markdown
@项目经理 请梳理以下任务的分工：

[任务描述]

相关智能体：[列出涉及的智能体]
```

### 5.4 不知道该找谁

#### 解决方案
```markdown
@AI使用工程师 我需要完成[任务描述]，应该找哪个智能体？
```

## 六、使用误区与禁忌

### 6.1 常见误区

| 误区 | 正确做法 |
|------|----------|
| 一次性给太多任务 | 分阶段、分批次下达 |
| 指令模糊不清 | 使用模板，明确要求 |
| 跳过审核环节 | 所有产出都要审核 |
| 忽略上下文管理 | 定期压缩，分阶段对话 |

### 6.2 禁止事项

| 禁止 | 原因 |
|------|------|
| 直接让AI"优化代码" | 可能引入新问题，必须明确优化目标 |
| 跳过架构设计直接开发 | 容易返工，浪费时间 |
| 不指定验收标准 | 无法判断任务是否完成 |
| 同时调度超过3个智能体 | 协调成本高，容易混乱 |

## 七、阶段性使用方案

### 7.1 项目启动阶段

**主要交互对象**：老板、AI使用工程师、项目经理

**典型操作**：
```
@老板 请审计以下需求：[需求描述]

@AI使用工程师 请帮我梳理需求，优化指令表达
```

### 7.2 设计阶段

**主要交互对象**：架构师、量子科学家、工程规则管理师

**典型操作**：
```
@架构师 请设计系统架构
@量子科学家 请计算实验参数
@工程规则管理师 请审核设计方案
```

### 7.3 开发阶段

**主要交互对象**：硬件工程师、软件工程师、工程规则管理师

**典型操作**：
```
@硬件工程师 请完成[具体模块]开发
@软件工程师 请完成[具体功能]开发
@工程规则管理师 请审核代码
```

### 7.4 验收阶段

**主要交互对象**：项目经理、老板

**典型操作**：
```
@项目经理 请汇报项目完成情况
@老板 请验收最终交付物
```
