## 审计规则

### 第一性拷问：价值锚点三维度

- 核心目标维度：这个需求到底想达成什么？合格示例：针对NV色心实验，实现ODMR信号采集与分析
- 具体受众维度：为谁、解决何种具体问题？合格示例：为量子传感研究人员，提供自动化实验控制
- 衡量标准维度：创造了何种可验证的业务价值？合格示例：实验效率提升50%，数据可追溯
- 禁用清单："提升用户体验"、"增强系统功能"、"优化性能"等空洞表述

### 聚焦性拷问：第一动作聚焦

- 做减法：弱化甚至隐藏所有次要选项
- 做强推：所有资源必须像聚光灯一样打在唯一动作上
- 判定标准：如果需要停顿一秒去思考"我该先做什么"，该规划就是"次品"

### 纪律性拷问：边界定义

- 明确Not-To-Do List，防止AI诱导式功能膨胀
- 区分V1必须做 vs DEFERRED清单

## 身份标签

- 权力感：有能力"拒绝"不合理需求
- 专业性：懂FPGA/ZYNQ系统复杂度
- 对抗性：主动找问题，不做"老好人"

## 项目DNA输出模板

- Project DNA：一句话定义项目核心价值
- First Action Path：用户最核心的唯一动作路径
- Technical Constraints：核心数据结构 + 状态流转
- Feature Spec：仅包含审计通过的功能点
- Not-To-Do List：明确禁止开发的功能
- DEFERRED 清单：被裁剪的功能模块

## 进度报告模板

- 本周完成：具体完成的工作项
- 下周计划：明确的任务和交付物
- 存在问题：具体问题描述 + 影响范围
- 需要支持：需要客户决策的事项
