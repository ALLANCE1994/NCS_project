## 一、质量底线思维

### 1.1 质量第一原则

**核心理念**：质量是设计出来的，不是测试出来的。

| 阶段 | 质量投入 | 质量成本 |
|------|----------|----------|
| 设计阶段 | 高 | 低 |
| 开发阶段 | 中 | 中 |
| 测试阶段 | 低 | 高 |
| 运维阶段 | 极低 | 极高 |

### 1.2 零缺陷理念

**目标**：第一次就把事情做对。

**实践方法**：
- 需求明确，避免理解偏差
- 设计评审，发现潜在问题
- 编码规范，减少低级错误
- 测试覆盖，确保功能正确

## 三、硬件开发安全通用准则

### 3.1 时序安全

#### 时钟域处理
```vhdl
-- 单bit信号跨时钟域：打两拍
signal sync_ff1, sync_ff2 : std_logic;
begin
    process(clk_dst, rst_n)
    begin
        if rst_n = '0' then
            sync_ff1 <= '0';
            sync_ff2 <= '0';
        elsif rising_edge(clk_dst) then
            sync_ff1 <= signal_src;
            sync_ff2 <= sync_ff1;
        end if;
    end process;
```

#### 复位设计
```vhdl
-- 异步复位、同步释放
process(clk, rst_n)
begin
    if rst_n = '0' then
        -- 异步复位
    elsif rising_edge(clk) then
        -- 同步逻辑
    end if;
end process;
```

### 3.2 电气安全

#### IO电平匹配
- 确认IO电平标准（LVCMOS33/LVCMOS25等）
- 检查上下拉电阻配置
- 避免直接驱动大电流负载

#### 上电时序
```
上电顺序检查：
1. 电源稳定时间
2. 复位释放时序
3. 配置完成信号
4. 系统初始化完成
```

### 3.3 资源安全

#### 资源使用上限
| 资源类型 | 安全上限 | 警告阈值 |
|----------|----------|----------|
| LUT | 80% | 70% |
| FF | 80% | 70% |
| BRAM | 80% | 70% |
| DSP | 80% | 70% |
| IO | 90% | 80% |

#### 时序收敛
```
建立时间（Setup）：
- 必须满足：T_setup ≤ T_clk - T_co - T_logic
- 裕量要求：≥ 0.5ns

保持时间（Hold）：
- 必须满足：T_hold ≤ T_co + T_logic
- 裕量要求：≥ 0.2ns
```

## 四、科研项目流程管控通用守则

### 4.1 阶段评审

| 阶段 | 评审内容 | 通过标准 |
|------|----------|----------|
| 需求评审 | 需求完整性、可行性 | 需求基线确认 |
| 设计评审 | 架构合理性、接口定义 | 设计文档通过 |
| 代码评审 | 编码规范、逻辑正确 | 无致命缺陷 |
| 测试评审 | 测试覆盖、用例质量 | 测试计划通过 |
| 验收评审 | 功能完整、质量达标 | 验收报告签字 |

### 4.2 变更控制

#### 变更流程
```
变更申请 → 影响分析 → 审批决策 → 实施变更 → 验证确认
```

#### 变更分级
| 级别 | 影响范围 | 审批权限 |
|------|----------|----------|
| 轻微 | 单个模块 | 技术负责人 |
| 中等 | 多个模块 | 项目经理 |
| 重大 | 系统架构 | 项目总监 |

### 4.3 文档管理

#### 文档完整性
```
必须文档：
- 需求规格说明书
- 系统设计文档
- 接口定义文档
- 测试计划与报告
- 用户操作手册
- 项目总结报告
```

#### 版本管理
```
版本号格式：v主版本.次版本.修订号

v1.0.0  正式发布
v1.1.0  功能增强
v1.1.1  缺陷修复
v2.0.0  重大重构
```

## 六、项目变更审核基础逻辑

### 6.1 审核维度

| 维度 | 审核要点 |
|------|----------|
| 必要性 | 变更是否必要？不变更的影响？ |
| 可行性 | 技术上是否可行？资源是否充足？ |
| 影响性 | 对进度、成本、质量的影响？ |
| 风险性 | 引入什么新风险？如何控制？ |

### 6.2 审核流程

```
提交变更申请
    │
    ▼
技术评审（可行性、影响分析）
    │
    ▼
管理评审（进度、成本影响）
    │
    ▼
审批决策（批准/拒绝/修改）
    │
    ▼
实施并验证
```
