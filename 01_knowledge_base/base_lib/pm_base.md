## VibeCoding三阶段详细说明

### 第一阶段：战略定型

- 核心理念：把"想做什么"变成"明确不做什么"
- 价值锚点可验证性检查：不仅是"解决什么问题"，更要定义"如何30秒内验证问题已解决"
- 示例：不是"实现脉冲控制"，而是"上电后30秒内成功发送第一条标准脉冲序列并读取回结果"
- 产出：脱水PRD、风险评估报告、MVP冻结规范

### 第二阶段：工程定型

- 核心理念：从"AI帮我写代码"到"AI在我的工程规则里工作"
- 产出：架构图、数据模型、Rules规则集

### 第三阶段：工程落地

- 核心理念：不再害怕AI改代码，随时可停、查、退
- 产出：可运行的系统、测试覆盖、可观测日志

## 阶段转换检查职责

### 战略定型到工程定型（必须全部满足）

- 项目DNA已输出（@C）
- Not-To-Do List已创建（@C）
- MVP冻结规范已输出（@P）
- 风险评估报告已通过@V审核

### 工程定型到工程落地（必须全部满足）

- 系统架构图已输出（@P）
- 接口定义文档已输出（@P）
- PS-PL划分方案已确定（@P）
- 技术选型文档已完成（@P）
- 参数计算报告已输出（@Q）
- 审核报告已通过@V审核

### 转换流程

- 收集产出物 -> 逐项验证 -> 缺失项输出 -> 全部满足后宣布进入下一阶段
- 阶段状态查询口令：查看项目阶段

## 三层回滚协调职责

- L1 Feature Flags：监督各代码产出Agent实现Feature Flag，审核新功能开启申请
- L2 git revert：L2回滚需项目经理确认，评估影响范围后授权执行
- L3 Worktree：协调严重问题的隔离修复工作，分配修复任务
- 回滚记录审核：审核所有回滚记录，确保原因清晰、影响明确、后续计划合理

## 波特图计划制定详细流程

### 为什么不用时间安排

- 时间压力导致步骤遗漏
- 为了赶进度而跳过必要检查
- 虚假进度（时间到了任务没完成）

### 核心要素

- 节点 = 任务（有明确交付物）
- 边 = 依赖关系（前置条件）
- 关键路径 = 决定项目最短完成时间的任务链

### 计划制定流程

- 列出所有必要任务（不遗漏任何步骤）
- 定义每个任务的交付物（可验证的产出）
- 确定任务间依赖关系（谁必须在谁之前）
- 绘制依赖关系图（Mermaid格式）
- 识别关键路径（最长依赖链）
- 标记就绪任务（无前置依赖，可立即开始）

### 节点定义格式

- 节点ID：唯一标识
- 任务名称：简明描述
- 负责人：@智能体
- 交付物：可验证的产出
- 前置条件：依赖的任务ID
- 状态符号：待启动/进行中/已完成/已验收/阻塞

### 状态符号

- 待启动
- 进行中
- 已完成
- 已验收
- 阻塞（需上报）

### 完成标准

- 交付物已产出并通过自检
- 交付物已通过@V审核
- 后置任务可正常启动

### 阻塞处理

- 任务阻塞时立即上报，不得等待
- 阻塞原因必须具体（等待谁的什么交付物）
- 提供解决方案或替代路径

## 任务分配模板

- 节点ID：任务标识
- 任务名称：具体任务描述
- 前置条件：已完成的前置任务或无
- 改动边界：仅处理指定范围，不涉及其他部分
- 目标状态：完成后应满足的条件列表
- 验收方式：具体验证步骤
- 阻塞上报：如遇阻塞，立即上报@M，不得跳过或假设
- 知识来源：基于哪份文档的哪个章节执行

## 进度汇报模板

### 日报模板

- 今日完成：具体完成的任务
- 明日计划：明确的任务安排
- 阻塞问题：需要协调的事项
- 风险预警：潜在风险点

### 周报模板

- 整体状态：总任务数/已完成/进行中/待启动/已阻塞
- 今日或本周完成任务：节点ID/任务名称/负责人/验收结果
- 就绪任务：节点ID/任务名称/负责人/前置条件已满足
- 阻塞任务：节点ID/任务名称/阻塞原因/解决方案
- 风险预警：风险描述 + 应对措施
- 需老板决策事项：决策描述 + 影响范围

## 任务状态流转格式

- 待启动 -> 进行中 -> 已完成 -> 已验收
- 进行中 -> 阻塞（需上报）
