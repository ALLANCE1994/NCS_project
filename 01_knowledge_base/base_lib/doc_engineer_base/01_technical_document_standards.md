> **适用角色**：资深文档工程师
> **知识类型**：通用基础能力
> **更新日期**：2026-05-16

---

## 一、文档撰写核心原则

### 1.1 读者导向

**核心思想**：文档是为读者服务的，不是为作者服务的。

| 读者类型 | 关注重点 | 文档特点 |
|----------|----------|----------|
| 项目管理者 | 进度、风险、资源 | 简洁、关键信息突出 |
| 技术开发者 | 实现细节、接口 | 详细、准确、可执行 |
| 测试人员 | 功能点、验收标准 | 清晰、完整、可验证 |
| 维护人员 | 架构、逻辑、变更 | 全面、追溯、易查 |
| 新成员 | 背景、流程、入门 | 友好、渐进、示例丰富 |

### 1.2 清晰性原则

**要求**：
- 使用简洁明了的语言
- 避免歧义和模糊表述
- 结构清晰，层次分明
- 适当使用图表辅助

**避免**：
- 冗长复杂的句子
- 专业术语不解释
- 信息堆砌无重点
- 假设读者已知

### 1.3 完整性原则

**必须包含**：
- 文档目的和范围
- 背景信息
- 详细内容
- 相关参考资料
- 版本历史

## 二、科研实验报告通用格式标准

### 2.1 标准结构

```
1. 标题
   - 实验名称
   - 实验日期
   - 实验人员

2. 摘要
   - 实验目的（1-2句）
   - 主要方法（1-2句）
   - 关键结果（1-2句）
   - 主要结论（1-2句）

3. 实验目的
   - 研究背景
   - 具体目标
   - 预期成果

4. 实验原理
   - 理论基础
   - 关键公式
   - 系统框图

5. 实验装置与方法
   - 仪器设备清单
   - 实验装置图
   - 实验步骤
   - 参数设置

6. 实验结果
   - 原始数据
   - 数据处理
   - 结果图表
   - 误差分析

7. 讨论与分析
   - 结果解释
   - 与理论对比
   - 误差来源分析
   - 改进建议

8. 结论
   - 主要发现
   - 研究意义
   - 后续工作

9. 参考文献

10. 附录
    - 原始数据
    - 详细计算
    - 补充材料
```

### 2.2 数据呈现规范

#### 表格规范
```markdown
| 参数 | 数值 | 单位 | 不确定度 |
|------|------|------|----------|
| 频率 | 2.87 | GHz | ±0.01 |
| 功率 | 10 | dBm | ±0.5 |

表1：实验关键参数
```

#### 图表规范
```markdown
- 图号：按章节编号（图1-1, 图1-2）
- 图题：位于图下方
- 坐标轴：标明物理量和单位
- 图例：清晰可辨
- 分辨率：足够清晰
```

### 2.3 公式书写规范

#### 行内公式
```markdown
零场分裂能级差为 $D \approx 2.87$ GHz
```

#### 独立公式
```markdown
$$\Delta E = h\nu = g\mu_B B$$

其中：
- $h$：普朗克常数
- $\nu$：频率
- $g$：g因子
- $\mu_B$：玻尔磁子
- $B$：磁场强度
```

## 四、图文排版统一基础要求

### 4.1 字体规范

| 元素 | 字体 | 字号 | 样式 |
|------|------|------|------|
| 正文 | 宋体/思源宋体 | 小四(12pt) | 常规 |
| 标题1 | 黑体 | 小二(18pt) | 粗体 |
| 标题2 | 黑体 | 三号(16pt) | 粗体 |
| 标题3 | 黑体 | 四号(14pt) | 粗体 |
| 代码 | Consolas/等宽 | 小五(9pt) | 常规 |
| 表格 | 宋体 | 五号(10.5pt) | 常规 |

### 4.2 段落规范

```
- 行距：1.5倍行距
- 段前：0行
- 段后：6磅
- 首行缩进：2字符
- 对齐方式：两端对齐
```

### 4.3 图表规范

#### 图片要求
```
- 格式：PNG（推荐）、JPG、SVG
- 分辨率：≥150 dpi（打印）、≥96 dpi（屏幕）
- 大小：宽度不超过页面宽度
- 颜色：RGB模式
```

#### 表格要求
```
- 边框：三线表（顶线、栏目线、底线）
- 对齐：表头居中，数值右对齐，文本左对齐
- 单位：在栏目名称中注明
- 表注：表下方说明
```

## 五、版本记录编写通用范式

### 5.1 版本号规则

#### 语义化版本
```
格式：主版本号.次版本号.修订号

示例：v2.1.3

主版本号（Major）：
- 不兼容的API修改
- 重大架构变更
- 从零开始计数

次版本号（Minor）：
- 向下兼容的功能新增
- 模块扩展
- 从零开始计数

修订号（Patch）：
- 向下兼容的问题修复
- Bug修复
- 从零开始计数
```

## 六、文档质量控制

### 6.1 自检清单

#### 内容检查
- [ ] 信息准确无误
- [ ] 逻辑清晰连贯
- [ ] 覆盖完整全面
- [ ] 示例正确可运行

#### 格式检查
- [ ] 标题层级正确
- [ ] 图表编号连续
- [ ] 引用格式统一
- [ ] 页眉页脚完整

#### 语言检查
- [ ] 无错别字
- [ ] 无语病
- [ ] 术语统一
- [ ] 标点正确

### 6.2 评审流程

```
作者自检
    ↓
同行评审（技术准确性）
    ↓
编辑评审（语言和格式）
    ↓
审批发布
```

### 6.3 维护更新

```
定期审查：
- 每季度审查一次
- 检查内容时效性
- 更新过时信息

触发更新：
- 产品版本升级
- 发现问题错误
- 收到用户反馈
- 法规标准变更
```
