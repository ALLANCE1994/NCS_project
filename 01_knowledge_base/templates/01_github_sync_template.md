## 一、同步口令

| 口令 | 功能 |
|------|------|
| `同步到GitHub` | 整理文件清单，生成提交说明，输出同步预览 |
| `查看仓库状态` | 显示本地与仓库的文件差异对比 |

---

## 二、同步流程

### 2.1 标准同步流程

```
客户：同步到GitHub
    │
    ▼
AI使用工程师执行：
1. 扫描本地产出物目录
2. 对比上次同步记录
3. 识别新增/修改/删除的文件
4. 按归类规则映射到仓库路径
5. 生成规范提交说明
6. 输出同步预览
    │
    ▼
客户确认预览内容
    │
    ▼
客户执行Git命令（或AI指导执行）
    │
    ▼
同步完成
```

## 四、提交说明规范

### 4.1 提交类型前缀

| 前缀 | 用途 | 示例 |
|------|------|------|
| `feat:` | 新功能/新文件 | `feat: 20260516 添加脉冲生成模块` |
| `update:` | 更新现有内容 | `update: 20260516 更新系统架构设计` |
| `fix:` | 修复错误 | `fix: 20260516 修正时序约束参数` |
| `docs:` | 文档更新 | `docs: 20260516 更新实验报告` |
| `refactor:` | 重构 | `refactor: 20260516 重构代码结构` |
| `sync:` | 批量同步 | `sync: 20260516 阶段性工作同步` |

### 4.2 提交说明模板

#### 单文件提交
```
feat: YYYYMMDD 添加[文件描述]

- 文件类型：[知识库/设计/代码/文档]
- 负责智能体：@[智能体名称]
- 主要内容：[一句话概括]
```

#### 阶段性批量同步
```
sync: YYYYMMDD 阶段性工作同步

- 新增：X个文件
- 修改：X个文件
- 删除：X个文件

主要更新内容：
1. [更新内容1]
2. [更新内容2]
3. [更新内容3]

相关智能体：@智能体A @智能体B @智能体C
```

#### 知识库更新
```
feat: YYYYMMDD 更新[知识库类型]知识库

- 更新类型：[新增/修改/删除]
- 涉及角色：[智能体名称]
- 知识块数：X个
- 来源文档：[文档名称]
```

## 七、Git命令指导

### 7.1 首次克隆（客户执行）

```bash
# 克隆仓库到本地
git clone https://github.com/ALLANCE1994/NCS_project.git

# 进入仓库目录
cd NCS_project

# 查看仓库状态
git status
```

### 7.2 日常同步（客户执行）

```bash
# 1. 进入仓库目录
cd /path/to/NCS_project

# 2. 拉取远程最新（避免冲突）
git pull origin main

# 3. 添加所有变更
git add .

# 4. 提交（使用AI生成的提交说明）
git commit -m "[提交说明]"

# 5. 推送到远程
git push origin main
```

### 7.3 查看历史

```bash
# 查看提交历史
git log --oneline -10

# 查看文件变更
git diff

# 查看仓库状态
git status
```

## 九、常见问题

### Q1: 首次使用如何绑定？
**A**: 已在配置中绑定仓库 `https://github.com/ALLANCE1994/NCS_project.git`，首次使用只需克隆到本地即可。

### Q2: 同步前需要做哪些准备？
**A**: 无需准备，直接输入 `同步到GitHub`，AI会自动整理文件清单和提交说明。

### Q3: AI会执行Git命令吗？
**A**: 不会。AI仅整理文件清单和生成提交说明，所有Git命令由客户确认后自行执行。

### Q4: 文件命名不规范怎么办？
**A**: AI会在同步预览中提示命名不规范的文件，并建议修正后的名称。

### Q5: 如何查看上次同步的内容？
**A**: 输入 `查看仓库状态` 或访问GitHub仓库查看提交历史。
