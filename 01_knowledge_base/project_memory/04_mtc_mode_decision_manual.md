# NV色心ZYNQ工程MTC智能体模式决策手册（唯一标准答案）

> **用途**：工程落地时的模式选择决策
> **适配**：Trae MTC 双任务智能体框架
> **原则**：稳定优先、适配场景

---

## 一、核心前提

本手册适配 Trae MTC 双任务智能体框架，基于"配置默认同步、运行隔离、文件共享"底层逻辑，仅用于工程落地时的模式选择决策，全程遵循"稳定优先、适配场景"原则。

---

## 二、分阶段最优模式选择（必选）

### 阶段1：框架优化/规则调整/统一改版（工程初期/迭代期）

| 项目 | 内容 |
|------|------|
| **最佳模式** | 1 - 统一同步模式 |
| **核心优势** | 双任务智能体配置实时互通，修改一处全局生效，方便统一完善分工、派单确认、调度流程，兼顾调试效率与规则统一性；对话运行互不干扰，工程资料共享，适合批量优化 MTC 体系 |
| **执行建议** | 无需额外操作，默认启用即可，优化完成后切换至下一模式 |

### 阶段2：正式开发/硬件调试/实验实测/项目量产（工程主力阶段）

| 项目 | 内容 |
|------|------|
| **最佳模式** | 2 - 全局锁定模式（**工程长期首选，核心推荐**） |
| **核心优势** | 冻结全部智能体配置，调度逻辑、派单流程、确认步骤、权责划分完全固定，杜绝框架变动干扰工程业务，专注硬件设计、代码开发、NV 实验测试，最大化保障项目稳定性，零规则出错风险 |
| **执行建议** | 正式开工前一键启用，直至项目阶段性完成，期间不随意解锁 |

### 阶段3：双任务并行（一边改框架、一边跑正式工程）

| 项目 | 内容 |
|------|------|
| **最佳模式** | 3 - 单角色锁定模式 |
| **核心操作** | 仅锁定高频使用的核心智能体（@A 调度管家、@H 硬件研发、@P 架构师），其余智能体正常同步更新，兼顾正式工程稳定性与框架迭代需求，避免顾此失彼 |

### 阶段4：双任务独立迭代（不同版本/不同方案并行）

| 项目 | 内容 |
|------|------|
| **最佳模式** | 4 - 彻底隔离模式 |
| **核心优势** | 两套智能体体系完全拆分，两边配置修改互不影响，可独立调试不同项目版本、不同技术方案，适合多方案对比测试 |

## 三、特殊场景补充选择

| 场景 | 模式 |
|------|------|
| 改完框架规则后，需立即同步双任务 | 5 - 配置刷新模式（一键加载最新规则） |
| 全局锁定后需重新迭代框架 | 6 - 全部解锁模式（恢复默认同步） |
| 需共用规则但隔离项目数据 | 7 - 规则同步+文件隔离模式 |
| 双任务协同开发、共享所有资源 | 8 - 全量全开互通模式 |

---

## 四、最终通用决策准则（优先级排序）

| 优先级 | 场景 | 模式 |
|:------:|------|------|
| **1** | 正式开工做项目（核心场景） | 2 - 全局锁定模式 |
| **2** | 优化框架、统一规则（迭代场景） | 1 - 统一同步模式 |
| **3** | 双任务并行（兼顾场景） | 3 - 单角色锁定模式 |
| **4** | 多版本测试（特殊场景） | 4 - 彻底隔离模式 |
| **5** | 临时调整（刷新/解锁等） | 对应补充模式 |

## 六、触发规则（主动弹窗 vs 保持安静）

### 1. 自动主动列出模式选择清单的场景

| 序号 | 触发条件 |
|:----:|----------|
| ① | 用户提及切换工程工作阶段（框架优化、正式开发、项目量产、版本测试） |
| ② | 用户提到双任务共用、分开使用、同步规则、冻结配置相关内容 |
| ③ | 用户新建任务、合并工程、拆分项目环境 |
| ④ | 出现智能体调度异常、配置不同步、分工错乱等问题 |
| ⑤ | 用户表达想要稳定运行、固定规则、改版调整框架这类意向 |
| ⑥ | 用户询问双任务搭配使用方案、框架落地适配方式 |

### 2. 日常正常工作状态，绝不主动弹出选择

| 序号 | 场景 |
|:----:|------|
| ① | 用户单纯下达技术任务、调度智能体完成研发工作 |
| ② | 正常做硬件设计、代码编写、实验调试、文档整理等常规业务 |
| ③ | 无任何调整同步模式、修改配置规则、切换运行状态的相关表述 |
| ④ | 仅专注项目内容推进，无环境与框架调整需求 |

### 3. 需要用户主动开口才提供选择的情况

用户明确说出：**"帮我选一下运行模式"、"调整双任务同步方式"、"切换智能体状态"** 这类话术，再调出决策手册给出选项。

### 4. 统一执行标准

```
非调整框架/非切换环境场景 → 只做事不打扰
触及环境、阶段、同步相关需求 → 立刻精简出数字选项
用户回复数字 → 自动完成配置
```
