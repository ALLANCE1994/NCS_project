# VibeCoding三阶段强制顺序规则

> **文档编号**：NV-RULE-VIBECODING-001
> **版本**：V1.0
> **生效日期**：2026-05-18
> **核心原则**：战略定型 → 工程定型 → 工程落地，不可跳步

---

## 一、三阶段定义

| 阶段 | 核心任务 | 一句话定义 | 主要产出 |
|------|----------|-----------|----------|
| **战略定型** | 把"想做什么"变成"明确不做什么" | 需求拆解 → 风险评估 → MVP冻结 | 项目DNA + Not-To-Do List + MVP冻结规范 |
| **工程定型** | 从"AI帮我写代码"到"AI在我的规则里工作" | 架构设计 → Rules驱动 → 领域建模 | 架构图 + 接口定义 + 参数计算 |
| **工程落地** | 不再害怕AI改代码，随时可停、查、退 | 小步快跑 → 三层回滚 → TDD保障 | 可运行系统 + 测试覆盖 + 可观测日志 |

---

## 二、阶段转换条件（强制）

### 2.1 战略定型 → 工程定型

**必须满足以下全部条件**：

| 序号 | 检查项 | 验证方法 | 责任人 |
|:----:|--------|----------|--------|
| 1 | 项目DNA已输出 | 检查文档存在 | @C |
| 2 | Not-To-Do List已创建 | 检查文档存在 | @C |
| 3 | MVP冻结规范已输出 | 检查文档存在 | @P |
| 4 | 风险评估报告已通过@V审核 | 检查审核报告 | @V |

**转换流程**：
```
战略定型完成检查
    │
    ├─ 全部满足 → 允许进入工程定型
    │
    └─ 有未满足项 → 返回完成缺失项
```

### 2.2 工程定型 → 工程落地

**必须满足以下全部条件**：

| 序号 | 检查项 | 验证方法 | 责任人 |
|:----:|--------|----------|--------|
| 1 | 系统架构图已输出 | 检查文档存在 | @P |
| 2 | 接口定义文档已输出 | 检查文档存在 | @P |
| 3 | 参数计算报告已输出 | 检查文档存在 | @Q |
| 4 | 审核报告已通过@V审核 | 检查审核报告 | @V |

**转换流程**：
```
工程定型完成检查
    │
    ├─ 全部满足 → 允许进入工程落地
    │
    └─ 有未满足项 → 返回完成缺失项
```

## 三、禁止跳步规则

### 3.1 禁止跳步清单

| 禁止跳步 | 检测方法 | 处理方式 | 风险 |
|----------|----------|----------|------|
| **跳过战略定型直接设计** | 检查项目DNA是否存在 | 返回完成战略定型 | 需求频繁变更，大量返工 |
| **跳过工程定型直接开发** | 检查架构图和接口定义是否存在 | 返回完成工程定型 | 设计缺陷，后期重构 |
| **跳过审核直接提交** | 检查审核报告是否存在 | 返回完成审核 | 质量问题流入下游 |

### 3.2 跳步检测机制

```
阶段开始时
    │
    ▼
检查上一阶段完成条件
    │
    ├─ 全部满足 → 允许进入本阶段
    │
    └─ 有未满足项 → 
        ├─ 输出提示：缺少XXX，请先完成上一阶段
        └─ 禁止进入本阶段
```

### 3.3 跳步违规处理

| 步骤 | 动作 | 执行人 |
|:----:|------|--------|
| 1 | 立即停止当前工作 | 对应智能体 |
| 2 | 输出缺失项清单 | @M |
| 3 | 返回上一阶段完成缺失项 | 对应智能体 |
| 4 | 记录跳步违规 | @V |
| 5 | 重新进入当前阶段 | 对应智能体 |

## 四、各阶段入口/出口条件

### 4.1 战略定型阶段

**入口条件**：
- 客户提出新需求或项目启动

**出口条件**：
| 序号 | 产出物 | 负责人 | 验收标准 |
|:----:|--------|--------|----------|
| 1 | 项目DNA | @C | 包含价值锚点、第一动作、边界定义 |
| 2 | Not-To-Do List | @C | 明确禁止的功能清单 |
| 3 | MVP冻结规范 | @P | 状态数≤3，线性无分支 |
| 4 | 风险评估报告 | @V | 三维过滤网全部通过 |

### 4.2 工程定型阶段

**入口条件**：
- 战略定型阶段出口条件全部满足

**出口条件**：
| 序号 | 产出物 | 负责人 | 验收标准 |
|:----:|--------|--------|----------|
| 1 | 系统架构图 | @P | Mermaid可渲染，模块关系清晰 |
| 2 | 接口定义文档 | @P | 信号、方向、位宽、功能完整 |
| 3 | 参数计算报告 | @Q | 有公式推导和知识来源 |
| 4 | 审核报告 | @V | 三维过滤网全部通过 |

### 4.3 工程落地阶段

**入口条件**：
- 工程定型阶段出口条件全部满足

**出口条件**：
| 序号 | 产出物 | 负责人 | 验收标准 |
|:----:|--------|--------|----------|
| 1 | 可运行代码 | @H/@S | 编译通过，无错误 |
| 2 | 时序报告 | @H | WNS>0, TNS=0, WHS>0 |
| 3 | 测试报告 | @S | 核心功能100%覆盖 |
| 4 | 审核报告 | @V | 全部通过 |

## 五、阶段状态管理

### 5.1 阶段状态定义

| 状态 | 说明 |
|------|------|
| **未开始** | 阶段尚未开始 |
| **进行中** | 阶段正在执行 |
| **待审核** | 阶段产出待审核 |
| **已完成** | 阶段出口条件全部满足 |

### 5.2 当前阶段判断

```python
# 阶段判断逻辑
if 战略定型出口条件全部满足:
    if 工程定型出口条件全部满足:
        当前阶段 = "工程落地"
    else:
        当前阶段 = "工程定型"
else:
    当前阶段 = "战略定型"
```

### 5.3 阶段状态查询口令

输入 `查看项目阶段` 可查询当前所处阶段和完成情况。
