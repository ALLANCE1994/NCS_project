# P0_09 项目经理唤醒权限

> **规则优先级**：P0（最高优先级）
> **生效日期**：2026-05-19
> **制定人**：@C老板
> **执行人**：@P 项目经理
> **适用范围**：项目紧急响应场景

---

## 一、规则目的

确保项目在关键节点能够高效协调全部资源，避免因等待客户响应而延误工程进度。

---

## 二、规则内容

### 2.1 唤醒权限定义（强制）

@P 项目经理拥有**无条件唤醒全部智能体**的权限：

```
唤醒条件：
├── 项目关键节点到达
├── 多智能体协作需求
├── 紧急问题需要响应
└── 日常站会/评审会议

唤醒方式：
├── 无需客户同意
├── 无需提前申请
└── 即时生效执行
```

### 2.2 唤醒场景（示例）

| 场景 | 说明 | 响应时间 |
|------|------|----------|
| 每日站会 | 09:00例行同步 | 即时 |
| 阶段评审 | M2/M3等出口审核 | 即时 |
| 紧急问题 | Bug/风险需要处理 | 即时 |
| 资源协调 | 多智能体任务分配 | 即时 |
| 客户指令 | 需要全团队响应 | 即时 |

### 2.3 唤醒执行流程

```
@P发起唤醒
    ↓
无需等待客户确认
    ↓
全部智能体立即响应
    ↓
按@P指令执行任务
```

### 2.4 智能体响应义务（强制）

被唤醒的智能体必须：
- [ ] 立即停止当前工作（除非关键路径）
- [ ] 响应@P的唤醒指令
- [ ] 按优先级执行新任务
- [ ] 完成后报告@P

---

## 三、权限边界

### 3.1 @P可以执行

- 唤醒全部智能体
- 分配紧急任务
- 调整任务优先级
- 召集临时会议

### 3.2 @P不可以执行

- 修改P0级规则
- 越过阶段闸门（需@V审核）
- 更改技术方案（需@A确认）
- 批准合规例外（需@V确认）

---

## 四、执行示例

### 4.1 日常站会

```
@P: "09:00站会开始，@A @H @S @Q @V 请汇报进度"

各智能体立即响应，无需等待客户确认
```

### 4.2 紧急问题

```
@P: "发现关键Bug，@H请立即处理，@V协助审核"

@H立即停止当前工作，优先处理Bug
```

### 4.3 阶段评审

```
@P: "M2交付物已齐，召集评审会议，全员参加"

各智能体立即准备，按时参加会议
```

---

## 五、违规处理

| 违规情况 | 处理措施 |
|----------|----------|
| 智能体不响应唤醒 | @P记录，记入绩效 |
| 智能体延迟响应 | @P警告，影响任务分配 |
| @P滥用唤醒权限 | @C介入调查 |
