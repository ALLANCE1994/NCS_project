# 双层文档提炼工作流程规范

> **版本**：v3.0
> **生效日期**：2026-05-18
> **适用范围**：NV色心实验系统项目所有格式知识库文件处理
> **更新说明**：v3.0 新增「老板终审」环节，重大任务完成后需@C老板最终审核

---

## 一、流程概述

本项目采用**「通用粗处理 + 专业精提炼」**双层文档加工模式，确保文档处理效率与专业深度兼顾。支持项目所有常用资料格式。

```
客户上传任意格式文件
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 第一层：文档预处理工程师（粗加工）                             │
│ - 识别文件格式，选择对应解析工具                               │
│ - 提取文本/表格/代码内容                                      │
│ - 删除冗余、清洗格式                                         │
│ - 统一转换为标准Markdown初稿                                  │
│ - 识别领域、精准分发                                         │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────────────────────────────┐
│ 第二层：对应专业智能体（精加工）                               │
│ - 深度专业提炼                                               │
│ - 结合项目落地                                               │
│ - 输出干货文档                                               │
└─────────────────────────────────────────────────────────────┘
    │
    ▼
工程规则管理师审核
    │
    ▼
老板终审（重大任务必经环节）
    │
    ▼
本地归档存储（默认不自动入库）
    │
    ▼
客户手动确认 → 批量投喂知识库
```

## 二、支持格式总览

| 格式类别 | 支持格式 | 扩展名 | 解析工具 | 提纯方式 |
|----------|----------|--------|----------|----------|
| **PDF文档** | PDF | `.pdf` | pymupdf | 文本提取+结构保留 |
| **纯文本** | TXT | `.txt` | 直接读取 | 规整排版 |
| **Markdown** | MD | `.md` | 直接读取 | 结构保留 |
| **Word文档** | Word | `.doc`, `.docx` | python-docx | 文本+表格提取 |
| **Excel表格** | Excel | `.xls`, `.xlsx` | openpyxl | 表格完整保留 |
| **PPT课件** | PowerPoint | `.ppt`, `.pptx` | python-pptx | 文字要点提取 |
| **图片图文** | 图片 | `.png`, `.jpg`, `.jpeg`, `.bmp`, `.tiff` | OCR | 文字识别提取 |
| **源码脚本** | 各类代码 | `.vhd`, `.vhdl`, `.v`, `.sv`, `.py`, `.c`, `.h`, `.tcl`, `.xdc`, `.sh`, `.m` 等 | 直接读取 | 代码+注释完整保留 |
| **压缩包合集** | 压缩包 | `.zip`, `.tar`, `.tar.gz`, `.tgz`, `.rar` | zipfile/tarfile | 解压后批量处理 |

## 三、角色职责划分

### 3.1 文档预处理工程师（唯一入口）

#### 职责范围
| 维度 | 内容 |
|------|------|
| **唯一权限** | 全格式文件读取、文本提取、文件解析、格式初整理 |
| **工作内容** | 拆文档、清冗余、调格式、分章节、识领域、做分发 |
| **禁止事项** | 技术解读、原理分析、经验总结、专业提炼 |

#### 处理标准
- **删除内容**：封面、扉页、广告、水印、空白内容、无关附录、页眉页脚、批注、二进制文件、系统文件
- **保留内容**：完整正文、表格数据、代码内容、图表基础结构、核心章节
- **输出格式**：层级清晰、排版整洁的Markdown标准初稿
- **不做任何专业技术解读**

### 3.2 专业智能体（深度提炼）

#### 通用职责
- 仅接收来自**@文档预处理工程师**的规整初稿
- 不直接读取原始文件
- 结合本NV色心实验项目进行深度专业提炼

#### 各专业智能体分工

| 智能体 | 接收文档类型 | 提炼重点 |
|--------|-------------|----------|
| **量子科学家** | NV色心量子传感、ODMR实验、自旋物理 | 物理原理、实验方法、参数标准 |
| **硬件工程师** | ZYNQ/FPGA/Vivado、脉冲卡、采集卡 | RTL设计、时序约束、避坑经验 |
| **软件工程师** | PYNQ、Jupyter、Python上位机 | 驱动开发、数据处理、API使用 |
| **架构师** | 系统顶层架构、整体项目方案 | 架构设计、技术选型、接口规范 |
| **工程规则管理师** | 工程规范、流程制度、质量管控 | 审核标准、流程方法、管控经验 |
| **AI使用工程师** | AI使用技巧、MTC调度、指令优化 | 使用技巧、调度方法、避坑指南 |

## 四、两级提炼执行标准

### 4.1 第一层：预处理工程师（粗加工）

#### 执行清单
- [ ] 识别文件格式，选择对应解析工具
- [ ] 提取文件全部有效内容
- [ ] 识别并删除冗余内容
- [ ] 保留完整正文、表格、代码
- [ ] 统一段落层级和格式
- [ ] 转换为标准Markdown初稿
- [ ] 识别文档所属领域
- [ ] 生成预处理报告
- [ ] 精准分发至对应专业智能体

#### 输出物
1. **标准初稿**：`XXX_preprocessed.md`
2. **预处理报告**：包含文件信息、格式类型、处理结果、领域识别、分发对象

### 4.2 第二层：专业智能体（精加工）

#### 执行清单
- [ ] 阅读规整初稿，理解文档内容
- [ ] 结合NV色心实验项目背景
- [ ] 提炼核心技术要点
- [ ] 总结实操方法
- [ ] 明确参数标准
- [ ] 梳理避坑经验
- [ ] 形成落地思路
- [ ] 输出干货技术文档
- [ ] 提交工程规则管理师审核

#### 输出物
1. **深度提炼文档**：`XXX_refined.md`
2. **提炼摘要**：核心要点、方法、参数、经验总结

## 六、审核与入库流程

### 6.1 审核流程

```
专业智能体完成深度提炼
    │
    ▼
提交工程规则管理师审核
    │
    ├─ 审核通过 ──► 判断是否为重大任务
    │                   │
    │                   ├─ 重大任务 ──► 提交@C老板终审 ──► 本地归档存储
    │                   │
    │                   └─ 常规任务 ──► 本地归档存储
    │
    └─ 审核不通过 ──► 返回修改 ──► 重新审核
```

### 6.1.1 重大任务判定标准

| 任务类型 | 判定条件 | 是否需要老板终审 |
|----------|----------|------------------|
| 批量文档处理 | ≥10篇PDF/文档 | ✅ 需要 |
| 知识库建设 | 新建或大幅更新知识库 | ✅ 需要 |
| 架构设计 | 系统架构/模块划分方案 | ✅ 需要 |
| 核心代码开发 | 关键模块代码编写 | ✅ 需要 |
| 规则/流程修订 | 项目DNA层面规则变更 | ✅ 需要 |
| 单文档处理 | <10篇PDF/文档 | ❌ 不需要 |
| 日常调试 | 常规问题排查 | ❌ 不需要 |

### 6.1.2 老板终审内容

@C老板审核重点：
- 交付成果是否符合项目战略方向
- 任务执行是否遵循项目规则
- 是否存在遗漏或偏差
- 是否需要补充或调整

老板终审输出格式：
```
【@C老板终审】
- 审核结论：✅ 通过 / 🔴 驳回 / 🟡 需补充
- 审核意见：[具体意见]
- 后续指令：[如有]
```

### 6.2 审核标准

| 审核维度 | 检查项 |
|----------|--------|
| **内容准确性** | 技术要点是否正确、参数是否准确 |
| **格式规范性** | 是否符合Markdown规范、结构是否清晰 |
| **项目适配性** | 是否结合NV色心项目、是否具有可操作性 |
| **完整性** | 是否涵盖要点、方法、参数、经验 |

### 6.3 入库规则

1. **默认不入库**：所有精炼文档默认不自动向量化录入智能体知识库
2. **本地归档**：全部留存本地`01_knowledge_base/`对应目录
3. **手动确认**：由客户手动确认文档可用后，再下达统一指令批量投喂
4. **投喂指令**：
   ```
   @项目经理 请将以下文档批量投喂至向量知识库：
   - [文档列表]
   目标智能体：[智能体名称]
   ```

## 七、权限与协作约束

### 7.1 权限矩阵

| 角色 | 全格式读取 | 文档预处理 | 深度提炼 | 审核 | 入库 |
|------|-----------|-----------|----------|------|------|
| 文档预处理工程师 | ✅ 唯一权限 | ✅ | ❌ | ❌ | ❌ |
| 量子科学家 | ❌ | ❌ | ✅ 量子类 | ❌ | ❌ |
| 硬件工程师 | ❌ | ❌ | ✅ 硬件类 | ❌ | ❌ |
| 软件工程师 | ❌ | ❌ | ✅ 软件类 | ❌ | ❌ |
| 架构师 | ❌ | ❌ | ✅ 架构类 | ❌ | ❌ |
| 工程规则管理师 | ❌ | ❌ | ✅ 规范类 | ✅ | ❌ |
| AI使用工程师 | ❌ | ❌ | ✅ AI类 | ❌ | ❌ |
| 项目经理 | ❌ | ❌ | ❌ | ❌ | ✅ 手动投喂 |
| 客户 | ✅ 上传 | ❌ | ❌ | ❌ | ✅ 确认投喂 |

### 7.2 协作约束

1. **业务隔离**：文档预处理工程师不参与项目研发、决策、技术评审
2. **单向流转**：文件 → 预处理工程师 → 专业智能体，不可逆向
3. **无硬件调试**：所有工作仅为文档整理与知识梳理，不触发硬件操作
4. **格式无关性**：后续流程（领域分发→深度提炼→审核→归档→确认入库）对所有格式完全一致

## 十、附则

### 10.1 规范更新

本规范由项目经理负责维护，每次更新需通知所有相关智能体。

### 10.2 异常处理

如遇以下情况，立即上报项目经理：
- 文件损坏无法读取
- 格式识别失败
- 领域识别置信度低于50%
- 专业智能体无法完成深度提炼
- 审核不通过次数超过3次
- 压缩包密码保护
