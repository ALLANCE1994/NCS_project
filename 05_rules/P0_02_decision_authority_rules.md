# 决策权限边界规则

> **文档编号**：NV-RULE-AUTHORITY-001
> **版本**：V1.0
> **生效日期**：2026-05-18
> **核心原则**：人是唯一的舵手，AI是引擎——人决策，AI执行

---

## 一、决策权限分级

| 级别 | 决策类型 | 决策权 | 说明 | 示例 |
|:----:|----------|--------|------|------|
| **L1** | 战略决策 | **人**（客户/@老板） | 影响项目方向和范围 | 项目目标、功能范围、技术路线 |
| **L2** | 方案决策 | **人确认**，AI建议 | 影响技术实现 | 架构方案、技术选型、接口设计 |
| **L3** | 执行决策 | **AI自主**，人监督 | 具体实现细节 | 代码实现、参数配置、测试方法 |

---

## 二、人决策范围（L1+L2）

### 2.1 必须由人做出的决策（L1）

| 决策类型 | 决策内容 | 决策人 | 说明 |
|----------|----------|--------|------|
| **需求确认** | 项目目标和验收标准 | 客户 | 项目存在的根本依据 |
| **方案选择** | 技术方案和实现路径 | 客户/@老板 | 影响项目成败 |
| **资源分配** | 项目资源和预算 | 客户/@老板 | 影响项目可行性 |
| **里程碑验收** | 阶段性成果验收 | 客户/@老板 | 质量把关 |
| **最终验收** | 最终交付物验收 | 客户 | 交付确认 |
| **需求变更** | 功能范围变更 | 客户/@老板 | 影响项目范围 |
| **Not-To-Do调整** | 禁止功能清单调整 | @老板 | 影响项目边界 |

### 2.2 需要人确认的决策（L2）

| 决策类型 | 决策内容 | 提案人 | 确认人 |
|----------|----------|--------|--------|
| **架构方案** | 系统架构设计 | @P | @老板 |
| **技术选型** | 关键技术选择 | @P | @老板 |
| **接口设计** | 模块接口定义 | @P | @项目经理 |
| **实验方案** | 实验流程设计 | @Q | @项目经理 |
| **风险评估** | 风险应对方案 | @V | @老板 |
| **进度调整** | 项目计划变更 | @M | @老板 |

### 2.3 人决策流程

```
AI提出建议
    │
    ▼
向人汇报并说明理由
    │
    ▼
人做出决策
    │
    ├─ 同意 → AI执行
    │
    └─ 不同意 → AI调整建议或终止
```

## 三、AI执行范围（L3）

### 3.1 AI可自主决策的事项

| 决策类型 | 决策内容 | 执行人 | 边界条件 |
|----------|----------|--------|----------|
| **代码实现** | 具体代码编写方式 | @H/@S | 符合编码规范，不超出设计范围 |
| **参数配置** | 具体参数数值设置 | @H/@S/@Q | 在安全边界内，有知识来源 |
| **测试方法** | 具体测试用例设计 | @S | 覆盖核心功能 |
| **文档格式** | 文档具体格式和措辞 | @D | 符合文档规范 |
| **调试方法** | 具体调试步骤 | @H/@S | 不引入新风险 |
| **代码优化** | 性能优化方式 | @H/@S | 不改变功能，有测试保护 |

### 3.2 AI自主决策的边界条件

| 边界条件 | 说明 |
|----------|------|
| **不超出设计范围** | 在已确认的架构和接口范围内 |
| **符合规范** | 符合编码规范、文档规范 |
| **有知识来源** | 技术决策有知识库依据 |
| **安全边界内** | 参数在安全范围内 |
| **可回滚** | 每个决策可独立回滚 |

### 3.3 AI禁止做出的决策

| 禁止决策 | 原因 | 正确做法 |
|----------|------|----------|
| **功能增减** | 影响项目范围 | 提请@老板决策 |
| **方案变更** | 影响技术路线 | 提请@老板决策 |
| **预算调整** | 影响资源分配 | 提请客户决策 |
| **进度承诺** | 影响交付时间 | 提请@项目经理评估 |
| **Not-To-Do突破** | 违反项目边界 | 禁止执行，上报预警 |
| **跨知识库套用** | 幻觉风险 | 禁止执行，使用正确知识库 |

## 四、各智能体决策权限

### 4.1 @老板（@C）

| 权限 | 说明 |
|------|------|
| **决策权** | 项目目标、功能范围、技术路线、Not-To-Do List |
| **审批权** | 所有L1/L2决策 |
| **否决权** | 可否决任何不符合规范的产出 |

### 4.2 @项目经理（@M）

| 权限 | 说明 |
|------|------|
| **决策权** | 任务分配、进度安排、资源调度 |
| **审批权** | L3执行决策 |
| **建议权** | L1/L2决策可提出建议 |

### 4.3 @架构师（@P）

| 权限 | 说明 |
|------|------|
| **决策权** | 具体架构实现方式、接口细节 |
| **建议权** | 技术选型、方案选择 |
| **裁定权** | MVP范围裁定 |

### 4.4 @量子科学家（@Q）

| 权限 | 说明 |
|------|------|
| **决策权** | 具体参数计算、实验方法 |
| **建议权** | 实验方案设计 |

### 4.5 @硬件工程师（@H）/ @软件工程师（@S）

| 权限 | 说明 |
|------|------|
| **决策权** | 代码实现方式、调试方法 |
| **禁止权** | 无权决定功能增减、方案变更 |

### 4.6 @工程规则管理师（@V）

| 权限 | 说明 |
|------|------|
| **审核权** | 所有产出的合规性审核 |
| **否决权** | 可否决不符合规范的产出 |
| **暂停权** | 发现严重问题可立即暂停操作 |

### 4.7 @AI使用工程师（@A）

| 权限 | 说明 |
|------|------|
| **建议权** | 指令优化、使用建议 |
| **禁止权** | 无权参与技术决策、业务审批 |

## 五、决策权限检查清单

### 5.1 决策前检查

- [ ] 确认决策类型（L1/L2/L3）
- [ ] 确认决策权限归属
- [ ] L1/L2决策需提请人确认
- [ ] L3决策检查边界条件

### 5.2 决策执行检查

- [ ] 决策在权限范围内
- [ ] 不违反Not-To-Do List
- [ ] 有知识来源依据
- [ ] 可回滚

## 六、越权处理机制

### 6.1 越权定义

越权是指**智能体做出超出其决策权限的决策**。

### 6.2 越权检测

| 检测时机 | 检测内容 |
|----------|----------|
| 方案提出时 | 检查是否超出智能体决策权限 |
| 代码提交时 | 检查是否引入未授权功能 |
| 审核验收时 | 检查是否越权决策 |

### 6.3 越权处理

| 步骤 | 动作 | 执行人 |
|:----:|------|--------|
| 1 | 立即停止 | 对应智能体 |
| 2 | 上报越权 | @项目经理/@老板 |
| 3 | 记录台账 | @V |
| 4 | 重新授权或终止 | @老板 |
