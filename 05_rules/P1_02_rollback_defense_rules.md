# 三层回滚防线规则

> **文档编号**：NV-RULE-ROLLBACK-001
> **版本**：V1.0
> **生效日期**：2026-05-18
> **核心原则**：不再害怕AI改代码，随时可停、查、退

---

## 一、回滚防线架构

| 层级 | 防线名称 | 触发条件 | 执行方式 | 恢复时间 |
|:----:|----------|----------|----------|:--------:|
| **L1** | Feature Flags | 功能开关控制，随时关闭新功能 | 配置开关=false | 秒级 |
| **L2** | git revert | 代码提交后发现问题 | `git revert HEAD` | 分钟级 |
| **L3** | Worktree | 严重问题需要隔离修复 | `git worktree add` | 分钟级 |

---

## 二、强制执行规则

### 2.1 L1 Feature Flags（首选防线）

**适用场景**：新功能开发、实验性代码、不确定的修改

**执行要求**：
1. **任何新功能必须先实现Feature Flag开关**
2. Flag命名规范：`FEATURE_[模块名]_[功能名]`
3. Flag默认值：新功能默认关闭，验证后开启
4. Flag位置：统一配置文件或环境变量

**示例**：
```python
# config.py
FEATURE_PULSE_GENERATOR_V2 = False  # 新版脉冲发生器，默认关闭

# main.py
if config.FEATURE_PULSE_GENERATOR_V2:
    from pulse_v2 import PulseGenerator
else:
    from pulse_v1 import PulseGenerator
```

### 2.2 L2 git revert（次选防线）

**适用场景**：提交后发现Bug、功能不符合预期、引入回归问题

**执行要求**：
1. **每次提交必须可独立回滚**（禁止跨多个提交的原子修改）
2. 提交粒度：一个提交只做一件事
3. 提交信息必须清晰说明改动内容
4. 回滚前必须先评估影响范围

**执行流程**：
```bash
# 1. 查看最近提交
git log --oneline -5

# 2. 确认要回滚的提交
git show HEAD  # 查看最近一次提交内容

# 3. 执行回滚
git revert HEAD  # 创建一个新提交来撤销HEAD的改动

# 4. 推送回滚提交
git push origin main
```

### 2.3 L3 Worktree（终极防线）

**适用场景**：严重问题需要隔离修复、需要同时维护多个版本

**执行要求**：
1. 主工作区保持稳定，问题修复在独立worktree中进行
2. 修复完成后合并回主分支
3. 修复期间主分支可继续其他开发

**执行流程**：
```bash
# 1. 创建隔离工作区
git worktree add ../NCS_hotfix main

# 2. 在隔离工作区中修复
cd ../NCS_hotfix
# ... 进行修复 ...

# 3. 提交修复
git add .
git commit -m "fix: 修复XXX严重问题"

# 4. 合并回主分支
cd ../NCS_project
git merge --ff-only main

# 5. 清理worktree
git worktree remove ../NCS_hotfix
```

## 三、回滚决策权限

| 层级 | 决策权限 | 说明 |
|:----:|----------|------|
| L1 | 对应智能体可自行执行 | 功能开关，风险可控 |
| L2 | 需@项目经理确认 | 涉及代码回滚，需评估影响 |
| L3 | 需@老板确认 | 严重问题，需高层决策 |

---

## 四、禁止事项

| 禁止项 | 说明 |
|--------|------|
| ❌ 跳过回滚直接修改 | 发现问题必须先回滚，再修复 |
| ❌ 跨多个提交的原子修改 | 每个提交必须可独立回滚 |
| ❌ 无Flag的新功能代码 | 新功能必须有开关控制 |
| ❌ 强制推送覆盖历史 | 禁止 `git push --force` |

---

## 五、回滚记录要求

每次执行回滚必须记录：

```markdown
【回滚记录】
- 时间：YYYY-MM-DD HH:MM
- 层级：L1/L2/L3
- 原因：具体问题描述
- 执行人：@智能体名称
- 影响范围：受影响的模块/功能
- 恢复方式：具体回滚命令
- 后续处理：是否需要修复、何时修复
```
