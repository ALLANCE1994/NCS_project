# P0_06 阶段闸门强制机制

> **规则优先级**：P0（最高优先级）  
> **生效日期**：2026-05-19  
> **制定人**：@C老板  
> **执行人**：@V 工程规则管理师  
> **适用范围**：所有开发阶段（M0-M7）

---

## 一、规则目的

防止"跳步开发"，确保每个阶段出口条件满足后才能进入下一阶段，从根本上避免架构缺失、设计缺陷流入下游。

---

## 二、规则内容

### 2.1 阶段闸门检查（强制）

```
任何阶段开始前，必须检查上一阶段出口条件
├── 检查通过 → 允许进入本阶段
└── 检查不通过 → 禁止进入，返回完成缺失项
```

### 2.2 合规报告（强制）

- @V必须在每个阶段结束时出具合规报告
- 报告必须包含：出口条件检查表、问题清单、整改建议
- 无合规报告，视为该阶段未完成

### 2.3 阶段进入审批（强制）

- 未通过@V审核，禁止进入下一阶段
- 用户指令若违反阶段顺序，必须拒绝并说明原因
- 强行进入视为严重违规，强制回退

### 2.4 违规处理（强制）

| 违规情况 | 处理措施 | 责任人 |
|----------|----------|--------|
| 未审核即进入下一阶段 | 强制回退，已工作作废 | @V执行 |
| 用户强压跳过阶段 | 记录并拒绝，上报@C | @V执行 |
| 隐瞒阶段状态 | 全员通报，记入档案 | @V记录 |

---

## 三、执行方式

### 3.1 代码/脚本标记

在TCL脚本、Makefile、代码中添加阶段检查标记：

```tcl
# Vivado TCL脚本示例
# 【阶段闸门检查】M2出口条件检查
set m2_checklist {
    "系统架构图"      "待检查"
    "模块接口定义"    "待检查"
    "引脚分配规划"    "待检查"
    "时序预算分析"    "待检查"
    "AXI寄存器映射"   "待检查"
}

# 调用@V检查
if {![check_stage_gate "M2" $m2_checklist]} {
    puts "ERROR: M2出口条件未满足，禁止进入M3"
    exit 1
}
```

### 3.2 每日合规检查

@V每日检查各智能体工作边界：
- 当前所处阶段
- 本阶段完成进度
- 是否存在跳步风险

### 3.3 用户指令拦截

当用户指令违反阶段顺序时：

```
用户："继续M3.0"
系统：
"⚠️ 阶段闸门拦截
当前阶段：M2（系统架构定型）
M2出口条件：
  ❌ 系统架构图 - 未输出
  ❌ 模块接口定义 - 未输出
  ❌ 引脚分配规划 - 未输出
  ...

无法进入M3，请先完成M2交付物。
是否查看M2任务清单？"
```
