## Level 2：跨角色交叉协作测试（6条链路）

### 测试内容
验证关键角色间的协作协议是否双向定义、格式兼容、路径畅通。

### 初始发现 & 修复记录

| 链路 | 协作方向 | 初始状态 | 修复动作 | 复测 |
|:----:|----------|:--------:|---------|:----:|
| 1 | @C老板 → @M项目经理 | PASS | - | PASS |
| 2 | @M项目经理 → @P架构师 | PASS | - | PASS |
| 3 | @P架构师 → @H硬件+@S软件 | **FAIL** | architect.md增加"技术规格下发协议"；HW/SW增加"接收架构师技术规格"章节 | PASS |
| 4 | @Q量子科学家 → @P架构师 | **FAIL** | quantum_scientist.md增加"科学需求输出协议"；architect.md增加"科学需求接收"章节 | PASS |
| 5 | @D文档预处理 → @E文档工程师 | PASS | - | PASS |
| 6 | @V规则管理师 → 全体 | PASS | - | PASS |

### 链路3修复详情
**问题**: 架构师定义了PS-PL技术拆分和接口模板，但缺乏向HW/SW传递的正式协议；HW/SW未定义从架构师接收设计输入的流程。

**修复**:
- `architect.md`: 新增"技术规格下发协议"（通过PM传递PS-PL划分方案、接口定义、时序性能约束）
- `hardware_engineer.md`: 新增"接收架构师技术规格"章节（PL端视角）
- `software_engineer.md`: 新增"接收架构师技术规格"章节（PS端视角）

### 链路4修复详情
**问题**: 量子科学家与架构师之间完全没有直接协作协议，物理参数到技术规格的转换链路缺失。

**修复**:
- `quantum_scientist.md`: 新增"科学需求输出协议"（关键参数清单、输出格式、传递路径、知识库交叉引用）
- `architect.md`: 新增"科学需求接收"章节（物理参数→工程量化指标→架构设计约束的转化流程）

### 复测结果
2项修复后重新检查，全部6条链路 **PASS**。
