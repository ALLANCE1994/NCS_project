> **版本**：V1.0

## 一、RAG溯源铁律（全员强制遵守）

### 1.1 强制溯源场景

输出以下**硬核技术内容**前，必须优先检索知识库：

| 类别 | 具体内容 |
|------|----------|
| **硬件类** | FPGA引脚定义、IP核配置参数、时序约束参数、IO标准 |
| **量子类** | NV色心物理参数、实验条件、脉冲序列、数据分析方法 |
| **软件类** | PYNQ API调用、Overlay配置、DMA传输参数、中断处理 |
| **架构类** | 系统架构方案、接口定义规范、模块划分方案 |
| **规范类** | 编码规范、文档规范、流程规范 |

### 1.2 溯源执行规则

| 场景 | 执行规则 |
|------|---------|
| **检索到权威匹配资料** | 严格依托原文内容整理输出，结尾必须标注知识来源，禁止私自篡改核心原意、禁止过度延伸脑补 |
| **未检索到有效对应知识库内容** | 立刻停止作答，明确告知"当前知识库中无对应专业资料，请上传相关文档后再执行"，绝不自行编造、凑答案、模糊蒙混、虚构参数与原理 |
| **日常管理沟通、项目进度规划等非技术类内容** | 无需强制溯源，正常自由输出 |

### 1.3 溯源优先级

| 优先级 | 来源类型 | 说明 |
|:------:|----------|------|
| 1 | 项目知识库 | 本项目投喂的专业文档 |
| 2 | 官方文档 | Xilinx官方文档、PYNQ官方文档 |
| 3 | 已发表文献 | 顶刊论文、权威教材 |
| 4 | 项目经验 | 参考项目经验汇总 |

## 二、知识来源标注格式（统一标准）

### 2.1 标准格式

```markdown
【知识来源】
- 文档名称：《XXX》
- 核心出处：第X章/第X节
- 关键内容：[原文核心描述]
```

### 2.2 标注示例

```markdown
【知识来源】
- 文档名称：《正点原子领航者ZYNQ开发指南》
- 核心出处：第5章 PS端外设配置
- 关键内容：UART0对应MIO 48-49，波特率默认115200
```

### 2.3 标注要求

| 要求 | 说明 |
|------|------|
| **必须标注** | 所有技术类输出 |
| **格式统一** | 使用上述标准格式 |
| **内容准确** | 出处和关键内容必须准确 |
| **可追溯** | 能够追溯到原文档 |

## 三、跨知识库隔离

### 3.1 禁止事项

| 禁止事项 | 说明 | 示例 |
|----------|------|------|
| **跨知识库挪用** | 挪用无关领域知识强行套用 | 将其他芯片参数套用到ZYNQ7020 |
| **跨项目套用** | 将其他项目的方案套用到本项目 | 将其他NV系统参数套用到本项目 |
| **使用未验证外部方案** | 使用未经知识库验证的外部技术方案 | 使用网上找到的未验证代码 |

### 3.2 隔离规则

```
知识库边界
    │
    ├─ 本项目知识库 → 允许使用
    │
    ├─ 官方文档 → 允许引用，需标注来源
    │
    └─ 外部来源 → 禁止直接使用，需先验证入库
```

## 四、幻觉错误分类

### 4.1 错误类型定义

| 错误类型 | 定义 | 示例 |
|----------|------|------|
| **虚构型** | 编造不存在的信息 | 虚构不存在的FPGA引脚 |
| **篡改型** | 篡改原文核心原意 | 修改原文参数数值 |
| **延伸型** | 过度脑补超出原文 | 原文只说A，推断出B |
| **混淆型** | 跨领域知识错误套用 | 将其他芯片参数套用到ZYNQ |
| **遗漏型** | 关键信息缺失导致错误 | 遗漏重要约束条件 |

### 4.2 幻觉高风险场景

| 场景 | 幻觉风险 | 防护措施 |
|------|---------|---------|
| FPGA引脚定义 | 虚构不存在的引脚 | 必须基于知识库中的引脚定义文档 |
| IP核参数配置 | 编造不支持的参数 | 必须基于官方文档或知识库 |
| NV色心参数 | 杜撰物理参数数值 | 必须基于知识库或已发表文献 |
| 实验条件 | 编造实验参数 | 必须基于实验指南或知识库 |
| PYNQ API调用 | 编造不存在的API | 必须基于PYNQ官方文档 |

## 五、防幻觉审核机制

### 5.1 审核范围

所有技术类交付成果，在正式流转、归档、入库之前，必须完成幻觉专项审核。

### 5.2 审核流程

```
技术交付物提交
    │
    ▼
【第一关】RAG溯源检查
    │ 检查是否标注知识来源
    │ 检查来源是否真实存在
    ▼
【第二关】内容真实性检查
    │ 核对知识库原文
    │ 验证参数数值准确性
    │ 确认技术描述正确性
    ▼
【第三关】逻辑一致性检查
    │ 检查是否存在自相矛盾
    │ 检查是否存在过度延伸
    │ 检查是否存在脑补内容
    ▼
审核结果：通过 / 驳回
```

### 5.3 审核不合格处理

| 处理方式 | 说明 |
|----------|------|
| **直接驳回** | 写明错误类型 + 正确知识依据 |
| **要求修改** | 明确指出需要修正的内容 |
| **记录台账** | 将幻觉问题记录至《项目AI幻觉错误汇总台账》 |
