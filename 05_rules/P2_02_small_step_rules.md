# 小步快跑全局规则

> **文档编号**：NV-RULE-SMALLSTEP-001
> **版本**：V1.0
> **生效日期**：2026-05-18
> **核心原则**：小步快跑，每步可验证，禁止顺手优化

---

## 一、小步快跑四控制法

| 控制项 | 说明 | 示例 |
|--------|------|------|
| **改动边界** | 明确允许改什么、禁止改什么 | "本次只处理脉冲模块，不涉及时序约束" |
| **目标状态** | 定义"修到什么程度算完成" | "修改后：时序满足、资源不超过80%" |
| **验收方式** | 定义如何验证完成正确 | "编译通过 + 时序报告无违例" |
| **禁止顺手优化** | 防止修Bug引入新问题 | "不进行任何重构或命名调整" |

### 1.1 四控制法模板

```markdown
【改动边界】仅处理XXX，不涉及YYY
【目标状态】完成后应满足：1)... 2)... 3)...
【验收方式】具体验证步骤：1)... 2)... 3)...
【禁止事项】不进行任何重构、命名调整或顺手优化
```

## 二、"小步"的具体标准

### 2.1 小步判定标准

| 维度 | 标准 | 说明 |
|------|------|------|
| **时间** | 1-3天可完成 | 超过3天需进一步拆分 |
| **范围** | 单一模块/单一功能 | 不跨模块修改 |
| **代码量** | <200行代码变更 | 超过需进一步拆分 |
| **可验证性** | 有明确的验证方法 | 能判断完成与否 |
| **可回滚性** | 可独立回滚 | 不依赖其他改动 |

### 2.2 任务拆分标准

| 原任务规模 | 拆分建议 |
|-----------|----------|
| >5天 | 必须拆分为多个子任务 |
| 3-5天 | 可拆分，视复杂度决定 |
| 1-3天 | 合适，可直接执行 |
| <1天 | 可合并相邻任务 |

### 2.3 拆分检查清单

- [ ] 每个子任务可在1-3天内完成
- [ ] 每个子任务有明确的改动边界
- [ ] 每个子任务有明确的验收方式
- [ ] 子任务之间依赖关系清晰
- [ ] 每个子任务可独立回滚

## 三、禁止顺手优化清单

### 3.1 禁止事项

| 禁止事项 | 原因 | 正确做法 |
|----------|------|----------|
| **顺手重构代码** | 引入新Bug，难以定位 | 单独任务处理重构 |
| **顺手改名** | 影响其他模块，破坏接口 | 单独任务处理命名 |
| **顺手加功能** | 功能膨胀，超出范围 | 提交新需求评估 |
| **顺手改接口** | 影响上下游，联调困难 | 单独任务处理接口 |
| **顺手优化性能** | 可能引入时序问题 | 单独任务处理优化 |
| **顺手加注释/文档** | 可能掩盖代码问题 | 单独任务处理文档 |

### 3.2 顺手优化检测

| 检测时机 | 检测内容 |
|----------|----------|
| 代码提交时 | 检查是否包含超出任务范围的改动 |
| 审核验收时 | 检查是否有顺手优化痕迹 |

### 3.3 顺手优化处理

| 步骤 | 动作 | 执行人 |
|:----:|------|--------|
| 1 | 识别顺手优化内容 | @V |
| 2 | 撤销顺手优化改动 | 对应智能体 |
| 3 | 记录顺手优化违规 | @V |
| 4 | 如需优化，单独提任务 | 对应智能体 |

## 五、小步快跑执行流程

### 5.1 任务接收

```
接收任务
    │
    ▼
评估任务规模
    │
    ├─ 符合小步标准 → 执行
    │
    └─ 超出小步标准 → 拆分后执行
```

### 5.2 任务执行

```
明确四控制法
    │
    ▼
执行改动（仅改动边界内）
    │
    ▼
验收验证
    │
    ├─ 通过 → 提交
    │
    └─ 不通过 → 修复（不改其他）
```

### 5.3 任务提交

```
检查是否包含顺手优化
    │
    ├─ 无顺手优化 → 提交
    │
    └─ 有顺手优化 → 撤销后提交
```

## 七、与大任务的处理

### 7.1 大任务拆分示例

**原任务**：实现完整的ODMR实验流程（预计2周）

**拆分后**：
| 子任务 | 预计时间 | 改动边界 |
|--------|----------|----------|
| 1. 微波源驱动开发 | 2天 | 仅微波源模块 |
| 2. 数据采集模块开发 | 2天 | 仅采集模块 |
| 3. 实验流程控制开发 | 2天 | 仅流程控制 |
| 4. 数据处理模块开发 | 2天 | 仅数据处理 |
| 5. Jupyter界面开发 | 2天 | 仅界面模块 |
| 6. 集成测试 | 2天 | 集成验证 |

### 7.2 拆分原则

1. **按模块拆分**：每个子任务对应单一模块
2. **按功能拆分**：每个子任务对应单一功能
3. **按层次拆分**：先底层后上层
4. **按依赖拆分**：先被依赖模块后依赖模块
