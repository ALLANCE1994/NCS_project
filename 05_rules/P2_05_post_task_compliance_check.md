# 任务后合规检查规则

> **规则编号**：P2_05  
> **优先级**：P2（标准优先级）  
> **生效日期**：2026-05-19  
> **维护责任**：【@V 工程规则管理师】  
> **触发时机**：每次任务执行完成后

---

## 一、规则目的

建立任务执行后的合规检查闭环，由@V工程规则管理师对执行过程和输出结果进行系统性核查，确保所有工作符合P0/P1规则、项目灵魂、角色职责和输出标准。

---

## 二、检查分层机制

| 任务类型 | 判定标准 | 检查深度 | 预计时间 |
|:--------:|----------|:--------:|:--------:|
| **简单任务** | 纯信息查询、确认/否定回答、简短对话 | 轻量检查 | 1-2分钟 |
| **标准任务** | 代码编写、文档撰写、常规设计 | 常规检查 | 3-5分钟 |
| **关键任务** | 架构设计、硬件配置、实验方案、跨智能体协作 | 深度检查 | 5-10分钟 |

### 2.1 任务类型判定流程

```
任务完成
    │
    ▼
@V判定任务类型
    │
    ├─ 纯查询/对话 → 轻量检查
    │
    ├─ 代码/文档/设计 → 常规检查
    │
    └─ 架构/硬件/实验/协作 → 深度检查
```

---

## 三、检查清单

### 3.1 P0规则合规检查（全部任务）

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| P0_01 | 规则层级遵守 | 未违反高优先级规则 |
| P0_02 | 决策权限 | 未越权决策，L1/L2/L3权限正确 |
| P0_03 | VibeCoding阶段 | 当前阶段工作符合阶段要求 |
| P0_04 | Not-To-Do执行 | 未执行禁止功能/行为 |
| P0_05 | 防幻觉溯源 | RAG溯源标注完整、来源真实 |

### 3.2 P1规则合规检查（标准/关键任务）

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| P1_01 | 防幻觉措施 | 无虚构/篡改/延伸/混淆/遗漏 |
| P1_02 | 回滚防线 | 关键操作有回滚预案 |
| P1_03 | 规划深度 | 任务拆解合理，规划完整 |
| P1_04 | 上下文质量 | 信息完整，引用准确 |

### 3.3 项目灵魂契合检查（关键任务）

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| 灵魂1 | RAG溯源 | 所有技术输出标注知识来源 |
| 灵魂2 | 防幻觉 | 无编造参数、虚构引文、杜撰原理 |
| 灵魂3 | 无伤节流 | 剔除冗余，保留干货，不压缩技术深度 |
| 灵魂4 | 调度本位 | @A未越权实操，已转派专职智能体 |

### 3.4 角色职责合规检查（全部任务）

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| 职责1 | 执行人匹配 | 任务由正确智能体执行 |
| 职责2 | 权限遵守 | 未超出该智能体权限范围 |
| 职责3 | 专业领域 | 工作内容符合智能体专业领域 |
| 职责4 | 交付物归属 | 交付物标注正确智能体 |

### 3.5 输出标准检查（标准/关键任务）

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| 标准1 | 格式规范 | 符合项目格式要求 |
| 标准2 | 内容完整 | 无关键信息遗漏 |
| 标准3 | 逻辑清晰 | 推理过程完整，无跳步 |
| 标准4 | 可追溯性 | 版本、时间、责任人明确 |

### 3.6 Vivado工程完整性检查（硬件任务）【新增】

> **适用范围**：M3.7+ PL端硬件开发任务

| 检查项 | 检查内容 | 合规标准 |
|:------:|----------|----------|
| **约束文件存在** | 必须包含约束文件 | ✅ 必须有pins.xdc + timing.xdc |
| **引脚约束** | 所有端口已分配IOSTANDARD | ✅ 不能有NSTD-1错误 |
| **LOC约束** | 所有端口已分配引脚位置 | ✅ 不能有UCIO-1错误 |
| **时钟约束** | 主时钟已定义 | ✅ create_clock |
| **时序约束** | 输入输出延迟已定义 | ✅ set_input/output_delay |
| **配置约束** | Bitstream生成配置完整 | ✅ COMPRESS、CRC等 |
| **TCL脚本** | 引用所有约束文件 | ✅ add_files |
| **交付物完整性** | 包含所有必需文件 | ✅ .xdc + .bit + .hdf |

**检查命令**：
```tcl
# 检查未约束端口
report_property -all [get_ports]
# 检查DRC错误
report_drc
```

## 四、检查执行流程

### 4.1 触发机制

```
任务执行完成
    │
    ▼
执行智能体输出"任务完成"信号
    │
    ▼
@V自动启动合规检查
    │
    ▼
按分层机制执行对应深度检查
    │
    ▼
输出检查结论
```

### 4.2 执行步骤

**步骤1：任务类型判定**（30秒）
- 回顾任务内容
- 对照分层标准判定类型

**步骤2：按清单检查**（根据深度1-10分钟）
- 轻量检查：P0规则 + 角色职责
- 常规检查：+ P1规则 + 输出标准
- 深度检查：+ 项目灵魂 + 全面复核

**步骤3：生成检查结论**（1-2分钟）
- 使用标准模板输出
- 逐条列出不合规项
- 给出整改建议

## 五、检查结论输出格式

### 5.1 轻量检查输出格式

```markdown
---
【@V 工程规则管理师】任务合规检查（轻量）
检查时间：YYYY-MM-DD HH:MM
任务类型：简单任务

✅ 合规结论：通过

检查项：P0规则 + 角色职责（5项）
- P0规则合规：✅
- 角色职责合规：✅

无需整改。
---
```

### 5.2 常规检查输出格式

```markdown
---
【@V 工程规则管理师】任务合规检查（常规）
检查时间：YYYY-MM-DD HH:MM
任务类型：标准任务

⚠️ 合规结论：有条件通过

【合规项】（10项）
✅ P0规则合规
✅ P1规则合规  
✅ 角色职责合规
⚠️ 输出标准：1项待改进

【不合规项】
| 序号 | 检查维度 | 具体问题 | 整改建议 |
|:----:|----------|----------|----------|
| 1 | 输出标准 | 代码注释率低于30% | 补充关键逻辑注释 |

【整改要求】
- 补充注释后重新提交
- @V复核通过后归档
---
```

### 5.3 深度检查输出格式

```markdown
---
【@V 工程规则管理师】任务合规检查（深度）
检查时间：YYYY-MM-DD HH:MM
任务类型：关键任务

❌ 合规结论：不通过，需整改

【检查汇总】（15项）
✅ P0规则合规（5/5）
⚠️ P1规则合规（3/4）- 1项问题
✅ 项目灵魂契合（4/4）
✅ 角色职责合规（4/4）
⚠️ 输出标准合规（3/4）- 1项问题

【不合规项详情】
| 序号 | 检查维度 | 规则条目 | 具体问题 | 严重程度 | 整改建议 |
|:----:|:--------:|----------|----------|:--------:|----------|
| 1 | P1规则 | P1_01 | 参数计算未标注知识来源 | 🔴 高 | 补充RAG溯源标注，指明来源文档 |
| 2 | 输出标准 | 标准3 | 实验步骤描述有跳步 | 🟡 中 | 补充中间步骤，确保可操作 |

【整改要求】
1. 补充参数计算的RAG溯源（来源文档+章节）
2. 完善实验步骤，补充第3-4步细节
3. 整改完成后重新提交@V审核

【风险提醒】
- 问题1涉及防幻觉，必须整改后才能流转
- 建议同步更新知识库，避免同类问题
---
```

## 六、不合规项处理流程

### 6.1 严重程度分级

| 级别 | 判定标准 | 处理方式 |
|:----:|----------|----------|
| 🔴 **致命** | 违反P0规则、防幻觉红线、硬件安全风险 | 立即驳回，必须整改 |
| 🟠 **高危** | 违反P1规则、关键信息遗漏、决策权限越界 | 驳回整改，@M介入 |
| 🟡 **中等** | 输出标准不符、格式不规范、轻微偏离 | 有条件通过，限期整改 |
| 🟢 **提示** | 优化建议、非强制改进项 | 通过，建议改进 |

### 6.2 整改闭环

```
不合规项指出
    │
    ▼
执行智能体整改
    │
    ▼
重新提交@V复核
    │
    ├─ 通过 → 归档
    │
    └─ 不通过 → 继续整改
```

## 七、特殊场景处理

### 7.1 多智能体协作任务

- 检查每个智能体的输出
- 检查协作接口一致性
- 检查整体流程合规性

### 7.2 跨阶段任务

- 检查阶段转换条件是否满足
- 检查各阶段工作是否符合阶段要求
- 检查阶段交付物完整性

### 7.3 紧急任务

- 可简化检查流程（但P0规则不可跳过）
- 事后补充完整检查
- 记录紧急原因
