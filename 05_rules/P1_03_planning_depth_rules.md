# 前期规划深度规则

> **文档编号**：NV-RULE-PLANNING-001
> **版本**：V1.0
> **生效日期**：2026-05-18
> **核心原则**：慢在前期，快在后期——前期多规划，后期少返工

---

## 一、"慢"的具体含义

"慢"不是拖延，而是**深度思考**：

| 维度 | "慢"的含义 | 跳步的后果 |
|------|-----------|-----------|
| **需求理解** | 充分理解需求，明确边界 | 需求频繁变更，大量返工 |
| **方案设计** | 多方案对比，选择最优 | 方案缺陷，后期重构 |
| **风险评估** | 全面识别风险，制定预案 | 风险爆发，项目延期 |
| **接口定义** | 清晰定义接口，文档先行 | 接口不匹配，联调困难 |

### 1.1 前期投入时间建议

| 阶段 | 建议时间占比 | 说明 |
|------|-------------|------|
| 战略定型 | 20-25% | 需求理解、MVP裁定、风险评估 |
| 工程定型 | 25-30% | 架构设计、接口定义、参数计算 |
| 工程落地 | 45-55% | 代码开发、测试验证、交付 |

### 1.2 前期规划核心产出

| 产出物 | 作用 | 后期依赖 |
|--------|------|----------|
| 项目DNA | 明确项目方向 | 所有决策的依据 |
| Not-To-Do List | 防止功能膨胀 | 开发边界检查 |
| MVP冻结规范 | 锁定V1范围 | 开发目标明确 |
| 架构图 | 模块关系清晰 | 开发分工依据 |
| 接口定义 | 模块交互标准 | 联调对接依据 |

## 三、禁止跳步规则

### 3.1 跳步定义

跳步是指**前一阶段未完成就进入下一阶段**。

### 3.2 禁止跳步清单

| 禁止跳步 | 原因 | 正确做法 |
|----------|------|----------|
| 需求未冻结就设计 | 需求变更导致设计返工 | 先完成战略定型 |
| 设计未审核就开发 | 设计缺陷导致代码返工 | 先完成工程定型 |
| 代码未审核就提交 | 质量问题流入下游 | 先通过@V审核 |
| 时序不满足就上板 | 硬件损坏风险 | 先满足时序要求 |
| 测试未通过就交付 | 功能缺陷流入生产 | 先通过测试验证 |

### 3.3 跳步检测机制

```
阶段开始时检查
    │
    ▼
上一阶段完成标志是否全部满足？
    │
    ├─ 是 → 允许进入本阶段
    │
    └─ 否 → 禁止进入，提示完成上一阶段
```

### 3.4 跳步违规处理

| 处理步骤 | 动作 | 执行人 |
|:--------:|------|--------|
| 1 | 立即停止当前工作 | 对应智能体 |
| 2 | 返回上一阶段完成缺失项 | 对应智能体 |
| 3 | 记录跳步违规 | @V |
| 4 | 重新进入当前阶段 | 对应智能体 |

## 四、规划深度检查清单

### 4.1 战略定型深度检查

- [ ] **价值锚点**：核心目标、具体受众、衡量标准全部明确
- [ ] **第一动作**：用户第一个动作唯一且明确
- [ ] **边界定义**：Not-To-Do List和DEFERRED清单完整
- [ ] **风险评估**：A/B/C三维过滤网全部检查
- [ ] **审批确认**：@老板审批通过

### 4.2 工程定型深度检查

- [ ] **架构设计**：模块划分清晰，依赖关系明确
- [ ] **接口定义**：所有接口信号、方向、位宽、功能完整
- [ ] **参数计算**：所有关键参数有公式推导和来源
- [ ] **技术选型**：选型理由明确，备选方案对比
- [ ] **审核通过**：@V审核通过

### 4.3 工程落地深度检查

- [ ] **代码规范**：符合编码规范
- [ ] **编译通过**：无错误，无Critical Warning
- [ ] **时序满足**：WNS>0, TNS=0, WHS>0
- [ ] **测试覆盖**：核心功能100%覆盖
- [ ] **审核通过**：@V审核通过

## 六、时间分配建议

### 6.1 标准项目时间分配

```
总工期：11-16周

战略定型（2-3周，约20%）
├── 需求理解：1周
├── MVP裁定：0.5周
└── 风险评估：0.5周

工程定型（3-4周，约25%）
├── 架构设计：1.5周
├── 接口定义：1周
└── 参数计算：0.5周

工程落地（6-9周，约55%）
├── 硬件开发：3-4周
├── 软件开发：2-3周
└── 联调测试：1-2周
```

### 6.2 前期规划不足的后果

| 前期规划不足 | 后期返工量 |
|-------------|-----------|
| 需求理解不充分 | 需求变更导致30-50%返工 |
| 方案设计不完整 | 设计缺陷导致20-30%返工 |
| 接口定义不清晰 | 联调问题导致15-25%返工 |
| 风险评估不全面 | 风险爆发导致10-20%延期 |
