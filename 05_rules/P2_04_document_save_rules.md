## 4. 保存确认规则

> **【@V 工程规则管理师】强制要求**：每次保存后必须在对应路径上确认确实保存了

### 4.1 确认流程

```
保存文件
    │
    ▼
执行保存操作（Write工具）
    │
    ▼
【@V 工程规则管理师】验证文件存在
    │
    ├─ 文件存在 → ✅ 确认保存成功
    │
    └─ 文件不存在 → ❌ 保存失败，重新执行
```

### 4.2 确认方法

| 方法 | 命令/操作 | 负责智能体 |
|------|-----------|-----------|
| 文件列表 | `LS` 工具查看目录 | 【@V 工程规则管理师】 |
| 文件读取 | `Read` 工具读取内容 | 【@V 工程规则管理师】 |
| 路径显示 | 在回复中显示完整路径 | 【@V 工程规则管理师】 |

### 4.3 确认输出格式

```markdown
### 【@V 工程规则管理师】保存确认报告

| 序号 | 文件名 | 保存路径 | 状态 |
|:----:|--------|----------|:----:|
| 1 | dds_generator.vhd | `03_code/01_vhdl_modules/dds_generator.vhd` | ✅ 已确认 |
```

## 6. 路径不确定处理规则（新增）

> **核心原则**：保存路径必须符合项目规范目录结构，禁止随意设置路径

### 6.1 路径选择流程

```
需要保存文件
    │
    ▼
查阅5.4规范目录
    │
    ├─ 找到合适路径 → 保存到对应目录
    │
    └─ 找不到合适路径 → 交给【@A AI使用工程师】处理
                          │
                          ▼
                      @A协调确定路径或创建新目录
```

### 6.2 禁止行为

- ❌ 随意在根目录创建文件夹
- ❌ 将文件保存到非规范路径（如`temp/`、`test/`等随意命名目录）
- ❌ 将文件保存到不匹配的目录（如将VHDL代码放到Python目录）
- ❌ 不确定路径时自行决定保存位置

### 6.3 @A处理流程

| 步骤 | 动作 | 执行人 |
|:----:|------|--------|
| 1 | 接收路径不确定的请求 | @A |
| 2 | 查阅项目架构和目录规范 | @A |
| 3 | 协调@P确定合适路径或创建新目录 | @A → @P |
| 4 | 反馈确认后的保存路径 | @A |
| 5 | 执行保存 | 原智能体 |

### 6.4 触发条件

以下情况必须交给@A处理：
- [ ] 查阅5.4规范目录后仍不确定保存位置
- [ ] 文件类型与现有目录分类不匹配
- [ ] 需要创建新的子目录分类
- [ ] 跨多个目录都有可能保存的情况
